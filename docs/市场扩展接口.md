## 2. 注册表接口

### 2.1 `data/markets.json` 字段

```jsonc
{
  "code": "US",                 // 必填。国家 ISO 3166-1 alpha-2 大写（US/GB/CN/TW…）；region 用区域码（EU）
  "kind": "country",            // 必填。country | region
  "parent": null,               // 必填。null 或已注册 region 代码（未来 EU 成员国：parent="EU"）
  "group": "NA",                // 启用必填。导航分组：NA / EUROPE / LATAM / ASIA / OCEANIA（可扩展但需改校验）
  "name": {"en": "United States", "es": "Estados Unidos", "zh": "美国"},  // 必填。站点 3 种 UI 语言都要有
  "i18n_key": "home.us",        // 启用必填。站点现有 i18n key：home.<code 小写>
  "flag": "🇺🇸",                // 启用必填。两个 regional indicator（国旗/区域旗）
  "source_id": "openfda_ndc",   // 启用必填。主来源，必须已在 DB `source` 表登记
  "extra_source_ids": ["medlineplus"],  // 可选。辅助来源，同样必须在 source 表
  "default_lang": "en",         // 必填。该市场默认 UI 语言，必须 enabled 且在 languages 里
  "languages": ["en"],          // 必填。该市场可用 UI 语言（country 不能为空）
  "enabled": true,              // 必填。disabled = 占位（不生成页面、不进国家选择器）
  "order": 10,                  // 必填。市场间唯一正整数（显示顺序）
  "notes": "……"                 // 可选。许可/数据口径/占位原因
}
```

校验规则（`lib/markets.py::_validate_markets`）：

- `code` 唯一、`^[A-Z]{2,3}$`；`order` 唯一；`flag` 合法且唯一；`name.en/es/zh` 齐全；
- `kind` 合法；`parent` 必须是 region 代码，region 不允许再有 parent（本轮只有一层区域）；
- **enabled** 市场：`source_id` 非空且存在于 DB `source` 表、`i18n_key` 匹配 `home.<code>` 且唯一、`default_lang` 是 enabled 语言、`languages` 全是 enabled 语言；
- **enabled region** 至少要有 1 个 enabled 子市场（防止「空区域上线」）；
- disabled 占位允许 `source_id=null`、`languages=[]`（仅 region），方便先占坑。

### 2.2 `data/languages.json` 字段

```jsonc
{
  "schema_version": 1,
  "planned_markets": ["DE", "FR", "IT", "NL", "PL", "PT"],  // 未来国家的占位（语言 default_country 可指向）
  "languages": [{
    "code": "zh-Hant",           // 必填。BCP47 片段（en / es / zh / zh-Hant / pt-BR…）
    "name": {"en": "Chinese (Traditional)", "es": "Chino tradicional", "zh": "繁体中文"},
    "native_name": "繁體中文",     // 必填。语言切换/About 用
    "ui_label": "繁中",           // 必填。语言切换按钮短标签（1–8 字符，唯一）
    "script": "traditional",     // 必填。latin / han / traditional / cyrillic / …
    "dir": "ltr",                // 必填。ltr | rtl
    "hreflang": "zh-Hant",       // 必填。<link rel=alternate hreflang> 值，唯一
    "path": "zh-Hant/",          // 必填。站点 URL 路径；en 用空串（根路径）；唯一
    "i18n_key_prefix": "zh-Hant",// 必填。站点 I18N 字典的段名（唯一）
    "default_country": "TW",     // 必填。默认国家：enabled 语言必须是 enabled 市场；disabled 可指向 planned_markets
    "region": "EU",              // 可选。语言占位的区域标签
    "enabled": false,            // 必填。当前启用：en/es/zh
    "order": 40,                 // 必填。语言间唯一
    "notes": "预留：需繁体文案 + TW 市场数据"
  }]
}
```

### 2.3 `lib/markets.py` API

```python
from lib import markets

reg = markets.load()                       # 读两个 JSON + 只读 DB source 表
reg.validate()                             # list[str]，空 = 通过
reg.enabled_markets                        # (Market("US"), Market("GB"), …) 按 order
reg.country_order                          # ("US","GB","CA","AU","ES","MX","CN") 国家页/选择器规范顺序
reg.languages_for_market("MX")             # (Language("es"),)
reg.market_for_language("zh-Hant")         # Market("TW")（disabled 也返回）
reg.hreflang_map()                         # {"en": "", "es": "es/", "zh": "zh/"}
reg.i18n_prefixes()                        # {"en": "en", "es": "es", "zh": "zh"}
reg.as_dict()                              # 合并导出（可写进构建产物/调试）
```

**dummy 注册（测试/未来热扩展用）**：`with_market()` / `with_language()` 返回新实例，不改原对象；非法条目抛 `ValueError`：

```python
reg2 = markets.load().with_market({
    "code": "ZZ", "kind": "country", "parent": None, "group": "GLOBAL",
    "name": {"en": "Dummyland", "es": "País Ficticio", "zh": "测试国"},
    "i18n_key": "home.zz", "flag": "🇿🇿", "source_id": "manual_seed",
    "default_lang": "en", "languages": ["en"], "enabled": True, "order": 95,
})
assert reg2.validate() == []
```

CLI：`python lib/markets.py [--check] [--json] [--no-db] [--markets PATH] [--languages PATH]`。

## 5. schema `market` 表迁移草案（**本轮不改 `db/schema.sql` / DB**）

现状问题：`product.country` 是 `CHECK (country IN ('US','GB','CN','ES','MX','AU','CA'))`（`db/schema.sql:80`）。
**SQLite 不能 `ALTER TABLE ... DROP/ADD CONSTRAINT`**，所以「加一个国家」目前必须**重建 product 表**（40 万+ 行）。
目标：把国家清单从 CHECK 挪到 `market` 表，用外键/触发器约束，新增市场只改数据行。

### 5.1 目标模型（草案 DDL）

```sql
-- 市场表：与 data/markets.json 一一对应（注册表是仓库真相源，此表是 DB 内真相源，
-- 由 db/init_db.py 从 data/markets.json 同步，或由迁移脚本一次性灌入）
CREATE TABLE IF NOT EXISTS market (
    code          TEXT PRIMARY KEY,                    -- US / GB / EU / TW
    kind          TEXT NOT NULL CHECK (kind IN ('country','region')),
    parent        TEXT REFERENCES market (code),       -- region 层级（EU 成员国）
    group_name    TEXT,                                -- 导航分组
    source_id     TEXT REFERENCES source (source_id),
    default_lang  TEXT NOT NULL,                       -- 不建 FK：语言注册表在文件层
    enabled       INTEGER NOT NULL DEFAULT 1 CHECK (enabled IN (0,1)),
    sort_order    INTEGER NOT NULL DEFAULT 100,
    flag          TEXT,
    name_json     TEXT NOT NULL,                       -- {"en":…,"es":…,"zh":…}（前端/About 用）
    notes         TEXT
);
CREATE INDEX IF NOT EXISTS idx_market_parent ON market (parent, sort_order);

-- product.country 改为引用 market：
-- 方案 A（推荐，更严格）：country TEXT NOT NULL REFERENCES market (code)  —— 但 SQLite 外键需 PRAGMA foreign_keys=ON
-- 方案 B（过渡）：保留 CHECK，但 CHECK 列表由迁移时从 market 表生成一次
-- 方案 C：保持无约束 + 迁移校验脚本（最弱，不推荐）
```

### 5.2 迁移步骤（`db/init_db.py` 幂等化）

1. **备份**：`data/drugs.db` → `data/backups/drugs-<utc>.db`（`run_all.py` 同款备份逻辑）。
2. **建 market 表**并灌入 `data/markets.json`（`INSERT OR REPLACE`；`enabled` 只入 1 的行；TW/EU 可先入 disabled 行或暂不入，建议全入以便未来启用）。
3. **重建 product 表**（SQLite 12 步标准流程）：

```sql
PRAGMA foreign_keys = OFF;
BEGIN IMMEDIATE;
CREATE TABLE product_new (
    ...同现有列定义，唯一差异：
    country TEXT NOT NULL REFERENCES market (code),
    ...其他列/约束不变...
);
INSERT INTO product_new SELECT * FROM product ORDER BY product_id;
DROP TABLE product;
ALTER TABLE product_new RENAME TO product;
CREATE INDEX IF NOT EXISTS idx_product_country ON product (country, status);
-- 重建依赖 product 的索引/视图（coverage 视图：DROP VIEW coverage; CREATE VIEW …）
COMMIT;
PRAGMA foreign_keys = ON;
PRAGMA foreign_key_check;   -- 空
PRAGMA integrity_check;     -- ok
```

4. **迁移检测**（`db/init_db.py` 幂等）：读 `sqlite_master.sql`，若 `product.country` 仍是旧 CHECK 枚举 → 跑重建；重建前检查磁盘空间与备份成功；可加 `schema_meta(key,value)` 记录 `market_schema=2`。
5. **同步注册表**：`lib/markets.py` 提供 `reg.country_order`；迁移脚本据此断言：迁移后 `SELECT DISTINCT country FROM product` == `reg.country_order`。

### 5.3 回滚

- 迁移失败/校验不过：`PRAGMA integrity_check` 报错 → 用备份整库替换回来（`data/backups/` 保留最近 5 份）。
- 已发布后回滚：恢复上一 tag 的建站产物 + DB 备份；`market` 表向下兼容（旧代码不读它）。

### 5.4 验收 SQL

```sql
SELECT COUNT(*) FROM product;                                    -- 迁移前后一致（记录 before/after）
SELECT country, COUNT(*) FROM product GROUP BY country ORDER BY country;  -- == registry.country_order
PRAGMA foreign_key_check;                                        -- 空
PRAGMA integrity_check;                                          -- ok
SELECT * FROM coverage ORDER BY country;                         -- 视图正常
```

### 5.5 风险

- `product` 表 40 万+ 行重建需要磁盘临时空间 + 秒级时间；迁移期间**禁止并行写库**。
- `coverage` 视图、`idx_product_country`、`dose_warning` 等依赖需一并重建。
- 迁移脚本必须可重复执行（幂等），且失败自动回滚事务。
- **本草案不在本轮执行**：本轮只把注册表与文档准备好；真正迁移由后续任务按 §3 步骤 7 排期。

## 7. EU（欧盟 region）接入 runbook（远景，暂不实现）

**为什么 EU 不能直接当国家做**：EU 不是统一药品市场——集中审批（EMA centralised procedure）之外，各国上市许可/商品名/包装/价格都不同；一个「EU 国家页」会把不同国家的产品混成一行，违反「国家 × 剂型 × 规格 × 成分」的身份原则。

1. **模型**：`EU` 只做 **region**（导航/筛选/聚合页），`kind=country` 的成员国市场用 `parent:"EU"` 挂上去；`product.country` 永远是国家代码，不写 EU。
2. **注册**：`data/markets.json` 已有 EU 占位（disabled）。成员国按 §3 逐个注册；EU region 在所有子市场 enabled 后置 `enabled:true`（校验强制：enabled region 必须有 enabled 子市场）。
3. **聚合页**（未来）：EU 页 = region 导航 + 「EMA 集中审批」标记 + 各成员国分行链接；**不生成产品页**。
4. **数据源**：EMA 公开数据（集中审批药品清单/EPAR）许可与再发布边界待确认；成员国数据源优先小市场试点（建议 **NL（CBG-MEB）/ IE（HPRA）/ DE（BfArM）** 择一两个），先英文 + 本地语言。
5. **语言**：EU 语言占位在 `data/languages.json`（de/fr/it/nl/pl/pt，全部 disabled）。实际开放顺序跟随试点市场规模，**不要一次开 24 种**；每开一种语言按 §4 走完整 7 步。
6. **schema**：`market.parent='EU'` 的层级在 §5 的 `market` 表中直接支持（一轮迁移完成，不需要为每个成员国再重建 product 表）。
7. **许可/合规**：EMA/各国监管数据多为「事实字段可引用、整库再发布需确认」；逐源写 `docs/许可清单.md`，About 页同步署名。
8. **验收**：EU region 不产生 `product.country='EU'` 行；子市场国家页正常；region 页只做导航。

预估：先 1–2 个成员国试点 + region 框架，2–3 周；不建议与 TW 同批做（schema 迁移与站点改造串行）。

## 9. 维护与纪律

- **注册表是单一真相源**：任何市场/语言变化先改 `data/*.json`，再改消费方（build/ETL/tests）；禁止在页面/脚本里新增硬编码国家或语言列表。
- **`enabled:false` 是安全默认**：数据源/许可/文案未就绪的占位一律 disabled，不进页面、不进索引。
- `lib/markets.py` 只读（JSON + DB `mode=ro`）；不做任何写库/建站动作。
- 改注册表后必须跑：`lib/markets.py --check` + `tests.test_markets_registry`；改站点接入后加跑 `site/build.py` 与三语测试。
- 数据库只读/写库纪律、发布纪律见 `AGENTS.md` §4/§6/§7：同一时间只有一个会话写 `data/drugs.db` 或跑 `site/build.py`。
- 变更记录：市场/语言新增写进 `CHANGELOG.md` 的版本节（用户可感知）；本文件 §1 的硬编码清单随改造更新。
