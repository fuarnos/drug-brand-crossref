## 0. 一句话

网站已有完整工具雏形，但**有几处数据展示错误会直接摧毁用户对结果的信任**——这比继续加市场、调配色重要得多。

## 1. P0：数据展示准确性（最高，先做）

| # | 现象（用户复现） | 根因方向 | 工位 |
|---|---|---|---|
| P0-1 | 搜 `Tylenol`：初步结果正常显示品牌；**完整索引加载后大量结果变成「无商品名」**，原名退到「命中名」里 | 分片索引与完整索引的**字段映射不一致**（名称/链接/身份必须加载前后一致） | search-alias |

| P0-3 | 成分页「也叫」里混入「宣传自己的商品」「生产厂家为突出」「硫酸氢氯吡格雷片是波立维」等整句 | 别名来源未清洗：**整句 / 说明文字 / 其他药品名**混进 `nickname`/alias | search-alias |

## 3. P2：次级页面可用性（第三）

| 页面 | 问题 | 改法 |
|---|---|---|
| 成分页 | 内容长；`+218`/`+200` 不易发现；「也在 US…」易被误解 | 顶部加市场 / 剂型 / 单方·复方筛选；`+N` → 「查看其余 N 个产品」；写清跨市场关联依据 |
| 商品名页 | 页面薄，无法核对具体记录 | 按市场分组的产品列表 + 完整规格 + 登记状态 + 原始来源 |
| 复方页 | 成分与含量无逐项对应；中文页有 `Brand`/`Dose` 英文表头 | 「产品—完整配方—剂型—市场—来源」表格 + 统一语言 |
| 分类页 | 成分旁堆叠在售/停售/撤市与市场码，扫描负担大 | 默认只突出成分名 + 覆盖市场；状态明细折叠；页内搜索与筛选 |
| 厂商页 | 声称 558 个只显示 60，无继续入口，重复行看不出差异 | 分页或加载更多 + 规格/登记号等区分字段（cap 已实测定 120 + JSON 三列） |
| 「按市场」入口 | 实际进覆盖表，不是该市场浏览页 | 改名「市场覆盖」**或**建市场入口页（「在此市场搜索」+ 类别 + 覆盖说明）；先做改名 |
| 警示页 | 「高严重度」与「待第二人复核」并置；来源常指向搜索页 | 风险级别与核验状态分开显示；尽量链到具体标签/文件/段落 |

## 4. P3：覆盖与说明口径统一（第四）

- 覆盖页开头说「记录数」、表头写「产品数」→ 统一术语并明确定义**登记记录 / 产品 / 名称 / 成分**。
- **墨西哥规格覆盖：覆盖页 35.2% vs 关于页 29%** → 必须同源生成。
- 关于页澳洲「无成分记录数量」与覆盖表映射数量需解释统计范围。
- 分类页把同市场的在售/停售/撤市并列在成分旁 → 易被误读为整体判断。
- 所有页面从**同一份统计摘要**生成数字；数据新鲜度显示「数据截至某日」，同步日期放次要位置。
- 关于页缩短：先答「能查什么 / 结果怎么理解 / 数据从哪来 / 有哪些限制」，字段名与脚本名移技术说明。

## 5. P4：流程与视觉（最后）

- **跨国查询三步**：① 输入药名（必要时选原药所在市场）② 确认具体产品的完整成分、规格、剂型 ③ 选目标市场看候选与差异。来源市场与目标市场必须分开（`?country=`=目标市场语义不动，新增 `?src=`）。
- Tylenol 结果顶部摘要要**明确概括的是哪一条候选产品**，不能让人以为确认了整个品牌。
- 压缩搜索结果上方重复说明（手机首屏被身份卡+提示占满）。
- 搜索后保留简洁顶部搜索栏（成分页/商品名页可续查）。
- 名称表达统一：市场「美国 US」；成分有可靠中文名时中文 + 原文；商品名保留原名。
- **增加不依赖 GitHub 账号的纠错入口**（当前门槛偏高）——需要人定形态（邮件 / 表单 / 第三方），先出方案。
