# 服务器迁移路线（v1.x，排在 UI 批之后）

> 决策口：用户 2026-10-30「你来想办法吧，我们后面可以租服务器」+「但是肯定是在 ui 改完之后了」。
> 结论：**现在不迁**；**UI 批（v0.9.6/v0.9.7）先做**；服务器迁移只在触发条件满足时启动，且按本文的「零重写」路径走。
> 本文只定方案，不动代码、不动 DB、不发版。作者：Lead（2026-10-30）。

---

## 0. 一句话

**把现在的静态站当「服务器架构的预渲染缓存」来组织**：前端只吃 `data/idx/*.json`（已有单点 `BASE`），后端上线后把这些 JSON 换成 `/api/*` 返回**同样的结构**，前端 0 改动 —— 迁移是换部署，不是重写。

## 1. 为什么现在不迁（成本对比）

| 维度 | 静态站（现状） | 服务器（未来） |
|---|---|---|
| 运维 | 0（`publish.ps1` 推送 gh-pages） | 需要：进程守护、备份、监控、TLS、DDoS |
| 成本 | 0 元 | VPS 2C4G 约 **$6–12/月** + 带宽（1–2 TB/月 通常够） |
| 性能 | Lighthouse 四页 99–100、LCP 0.9–1.7s；CDN 由 GitHub 承担 | 需自己做 CDN/缓存，冷启动与并发要调 |
| 体积 | **941.87 MB / 121,290 文件**，撞 900 MiB 自设上限 | dist 可降到 **~20 MB**（只留首页/静态页），长尾按需渲染 |
| 构建 | 全量 ~20 分钟/增量 ~20 分钟，121k 文件写盘 | 无需预渲染长尾，构建秒级 |
| 搜索 | 客户端 `core.json` 41.4 MB raw（9.83 MB gzip）首搜 | 服务端 SQL + 索引，首搜可 <100ms |
| 合规 | 只发布信息，主体轻 | 境内服务器需 **ICP 备案**；药品信息服务备案/许可需单独评估 |

**所以现在不迁是对的**：静态站零成本、零运维、SEO 已成型（sitemap 63,363）；迁移只解决「体积」和「长尾页」，而这两件事还没到非解决不可的程度。

## 1.5 中间路线：只换托管，不上服务器（比服务器便宜得多）

撞 900 MiB / 121k 文件的是 **GitHub Pages**，不是「静态站」本身。所以有一条更便宜的路：

| 路线 | 做法 | 成本 | 上限 | 代价 |
|---|---|---|---|---|
| 现状 | GitHub Pages + gh-pages | 0 | 仓库 ~1 GB、文件数不友好、构建 20 分钟 | — |
| **① 对象存储 + CDN（推荐先试）** | `publish.ps1` 改成 rsync/`aws s3 sync` 到 R2 或 S3，前置 Cloudflare | R2 **$0.015/GB/月**（1 GB ≈ **¥0.1/月**，出网走 Cloudflare 免费）；S3 略贵 | **无文件数上限、无 900 MiB 限制** | 无服务端搜索；部署脚本要改；域名/DNS 要切 |
| ② 服务器（本文 §3） | 动态渲染 + 只读 SQLite | $6–12/月 | 无 | 运维、ICP 备案、合规 |

> 也就是说：**「加长尾页」只解决体积问题，走 ① 就够**；**「要服务端搜索/账号级功能」才需要 ②**。UI 批之后先按 ① 评估，② 留作触发条件。


## 2. 触发条件（满足任意 2 条再动手）

1. **体积硬撞墙**：dist 逼近 900 MiB 且**必须**新增静态页（如全量单包装名字页 +285 MB）。
2. **必须的交互超出静态能力**：跨设备收藏/对比、账号级分享、需要服务端状态的功能（**注意：login 仍是产品红线，不因服务器而解禁**）。
3. **数据更新频率 > 每日一次**，静态重建不再够用。
4. **需要服务端搜索/排序/A-B/真实行为分析**，客户端索引成为瓶颈。
5. **构建时间**成为发布瓶颈（现在 20 分钟/次，发布窗口被卡死）。

## 3. 目标架构（最小改动）

```
浏览器 ──(同域 /api/*)──> FastAPI(只读) ──> SQLite data/drugs.db (mode=ro, 419.8 MB)
   │                          └── 缓存层（ETag / max-age）
   └── 静态资源：assets/{app,i18n,bilingual,boot}.js、style.css、顶层页
```

- **只读**：`mode=ro` 连接（与 `tests/trilingual/run_tests.py` 同写法），不提供任何写接口。
- 端点契约 = **现有 JSON 形状**（这样前端不动）：
  - `GET /api/core` → 现在的 `data/idx/core.json`（列式 + 字典编码，客户端 `decodeCore` 不变）
  - `GET /api/detail/<bucket>` → `data/idx/detail-*.json`
  - `GET /api/pinyin` → `data/idx/pinyin.json`
  - `GET /api/atc4/forms` → `data/idx/atc4-forms.json`（task-145）
  - 页面按需渲染：`/drug/<id>`、`/name/<slug>`、`/atc/<code>`、`/maker/<slug>` 服务端出 HTML（模板复用 `site/build.py` 的渲染函数，抽成 `render/` 模块）
- **前端取址单点**：`app.js` 第 40 行 `const BASE = (currentScript.src || location.href)…`、`boot.js` 的 `r` 变量已是单点；迁移时只改这一处常量（`window.__DATA_BASE__` 覆写），**禁止散落硬编码**。

## 4. 迁移五步 + 回滚

| 步 | 动作 | 验收 |
|---|---|---|
| 1 | 起 VPS（2C4G），Caddy/Nginx + TLS，只挂只读 SQLite | `curl /api/core` 与现状同 sha256 |
| 2 | 实现 4 个只读端点 + 页面渲染（复用 build.py 模板函数） | 与静态站逐页 diff（抽样 200 页） |
| 3 | 前端加 `__DATA_BASE__` 开关，默认仍指向静态 JSON | 静态模式回归：Lighthouse/三语检索不退化 |
| 4 | 灰度：新子域（`next.`）跑 1 周，sitemap 双发 | 线上行为指标对比（GoatCounter→自建统计） |
| 5 | DNS 切换 + 旧 gh-pages 保留 **30 天**（回滚用） | `verify_live.py` 对线上验收 |
| 回滚 | DNS 切回 gh-pages（静态站一直可用） | 10 分钟内恢复 |

## 5. 成本与合规（要提前算清，不是免费）

- **VPS**：2 vCPU / 4 GB / 40 GB SSD，$6–12/月；备份快照 +20%。
- **带宽**：现站 941 MB 全量体积，但真实流量远小于此（首搜 ~1.05 MB raw / 0.16 MB gzip）；1–2 TB/月 一般够。
- **CDN**：Cloudflare 免费层可挡大部分静态请求（注意其 Pages 产品有 20,000 文件上限，**装不下 121k 文件**，所以静态替代方案不可行）。
- **合规**：中国境内服务器需 **ICP 备案**；药品信息服务相关备案/许可需按当下规定核对（`docs/许可清单.md` 同步更新）；**用药建议 / 替代推荐 / 剂量换算仍然不做**，与服务器无关。
- **数据许可不变**：8 个 `non_redistributable` 来源仍只发派生层；服务器上线不得因此扩大再分发范围。

## 6. 排期时才做的 3 件零成本事（现在不做）

> 用户 2026-10-30：**「不要开始准备，排期就好了」** → 本节只在真正排期到该窗口时才执行。

1. **JSON 契约文档化**：把 `data/idx/*.json` 的字段、版本、缓存头写进 `docs/data-dictionary.md`（已有部分），迁移时直接当 API 契约。
2. **`BASE` 单点**：在 `site/build.py` 里加一条自检（禁止 `fetch('data/` 硬编码），保持迁移只需改一处。
3. **构建 manifest**：`site/build.py` 输出「页面 → 依赖的数据（成分/名称/市场）」清单，未来服务器可按需渲染，不用重建整站。
