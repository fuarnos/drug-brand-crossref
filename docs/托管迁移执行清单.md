## 3. 缓存与压缩策略（迁移成败的关键）

| 路径 | Cache-Control | 理由 |
|---|---|---|
| `/*.html` | `public, max-age=0, must-revalidate`（或 300s） | 版本页会变；靠 ETag 走 304，别让用户看到旧页脚版本 |
| `assets/*.js`、`*.css` | `public, max-age=31536000, immutable` | 文件名带 `?v=<hash>`，可长缓存 |
| `data/idx/*.json` | `public, max-age=3600` + 版本号 query | 首搜体积大，缓存收益最高；版本号已在 URL 里 |
| `drug/*`、`name/*`、`atc/*`、`combo/*`、`maker/*` | `public, max-age=3600`（内容随数据更新变） | 长尾页多、更新少，1 小时足够 |
| `sitemap.xml`、`robots.txt` | `max-age=600` | 每日更新 |
| 全部 | **Brotli 开启**，`Content-Type` 由扩展名决定（rclone 自动） | 现站 gzip 后 core 9.83 MB；Brotli 可再省 10–20% |

要点：**Cache-Control 必须按路径在 Cloudflare Cache Rules 里配**，不能只靠上传时统一 header（`sync_static.py` 打印的模板只是兜底）。

## 4. 验收标准（缺一不可）

1. `verify_live.py --expect-version vX.Y.Z`：**0 failures / 0 warnings**。
2. 首页体积与现站同量级（199,384 B ±10%）；`core.json` gzip 10.03 MB ±5%。
3. `sitemap.xml` **63,363** 条（或当版实测数）与 dist 一致；`robots.txt` 指向新域名。
4. 抽样 200 页：标题/canonical/hreflang 四语正确；404 页面返回 404 而非 200。
5. 中文/英文/西语各抽 3 条检索可用（含拼音、繁体）。
6. Lighthouse 移动端：四页 Performance ≥ 95（不应低于现站 99–100，若下降先查缓存与压缩）。
7. **回滚演练一次**：把 DNS 临时指回 gh-pages，确认 10 分钟内恢复。

## 5. 已知取舍

- **中国访问速度**：Cloudflare 免费 CDN 在境内不稳（可能 1–3s 首字节）。若中国用户占比高，应当走「阿里云 OSS + CDN」（需**备案域名**，成本约 5–20 元/月，取决于流量）。**这是迁移后看真实数据再决定的事**，不阻塞。
- **构建时间不变**：换托管只解决体积/文件数，`site/build.py` 仍是 ~20 分钟全量；要提速得上服务器动态渲染（`docs/服务器迁移路线.md` §3）。
- **不出网费**：R2 经 Cloudflare 回源/出网免费；若直连 S3 则出网费可能超过存储费。
- **发布入口不变**：仍然只走 `deploy/publish.ps1`，R2 同步是它内部的一步；不手工往 bucket 推。
