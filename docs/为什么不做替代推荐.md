# 为什么不做「替代药推荐」（判断依据，写给以后的自己）

> 起因：2026-10-30 朋友反馈里提「你可以在美国找到什么替代药 / 什么时候药性相似」。结论：**不做推荐，只做同成分跨市场对照与分类事实清单。**
> 本文是理由留档，避免以后每次有人问都重新讨论一遍。**红线在 `AGENTS.md` §1.3 / §9，改动需用户明确批准。**

## 三层原因（从硬到软）

### 1. 信息条件不成立

判断「A 能不能换 B」至少要知道：同成分（或同 ATC 类）、同剂型/释放机制、规格可比、**同适应症**、同给药途径、当地注册与供应状态。

库里只有**身份层**：`product`（country / dosage_form / form_base / route / release / status）、`substance`（INN / ATC / drug_class / DDD）、`product_component`（规格）。
**缺**：适应症、说明书剂量、禁忌、相互作用、疗程。缺字段硬推＝编。补这些字段意味着引入说明书全文数据（许可 + 体积 + 维护成本另算），且仍不解决个体化问题。

### 2. 责任与监管：资质是必要但不充分条件

- 跨市场「推荐替代」是个体化用药指导，不是信息服务。处方药须凭处方调配；面向公众推荐处方药在各市场都受限。
- 即使取得药品信息服务类备案/许可，也只解决「能发布信息」，不解决「能对个人给用药建议」——后者需要执业药师/医师审方、责任主体、留痕、免责与追溯。
- 本项目形态是**静态站 + 纯 AI + 无后端 + 无人工审方**，正好是这类责任的相反面。要做得另起产品，不是加一个 task。

### 3. 与自身核心价值直接冲突

站点的存在理由就是「商品名不是主键：同名可能不同药、同药可能很多名」。`collision` 视图现查 **severe 23,753 / warning 837**（共 192,665 个 name_key 有记录），结论全是「不可互换」。
一边警示「缓释不能换速释、盐型不同不等于等效」，一边推荐「该换哪个」，是自我否定，且真实用户会照做。

## 做替代（不做推荐）的四件事

| 做 | 边界 |
|---|---|
| 同成分跨市场对照（同 INN、同规格/剂型 → 各市场产品、状态、来源、数据日期） | 事实表，不排序、不推荐 |
| ATC 类目页 + 16 常见大类（1,154 个类目页 + task-145「同类 × 剂型 × 市场」事实清单） | 分类 ≠ 替代；同类不排序 |
| 引用既有 `collision` / `dose_warning` 的「不可互换」结论（盐型、缓释、复方 vs 单方） | 只复述已推导结论 |
| 把「要不要换」留给医师/药师，页面给可核事实与出处 | — |

## 如果将来真要往「替代」走

需要的不是一张证，而是一整套：执业药师审方流程 + 适应症/说明书数据授权 + 个体化信息采集 + 留痕与免责 + 逐市场合规评估 + 责任保险。那是医疗产品量级，需用户明确立项与预算，**不属于本仓库的自治范围**。

## 一句话

**把「能不能替代」留给医生，把「是不是同一个药、什么规格」做成事实表**——这是我们能做到的、也是用户真正需要的那一半。
