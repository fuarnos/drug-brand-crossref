# 药品商品名跨国定位站 · 方案 v0.1

> 状态：实施中。范围：**公开上线** / 美国 + 英国 + 中国 + 西班牙 + 墨西哥 + 澳洲 + 加拿大 / 只用可公开许可的数据源 + 离线抓取补全。
> 最后更新：2026-10-26

---

## 1. 这个站在解决什么

一句话：**给一个名字（或包装上的一行字），定位到它是哪个药、什么规格，再给出其他国家的对应产品。**

三个真实场景：

| 场景 | 输入 | 期望输出 |
|---|---|---|
| 拿到国外带回来的药 | 照片/手抄："Sortis 20 mg" | 阿托伐他汀 20 mg 片 → 英国 Lipitor 20 mg、中国立普妥 20 mg |
| 帮家人核对海淘药 | "Panadol" | 对乙酰氨基酚 500 mg → 美国 Tylenol、中国泰诺林（**并警告：中国「泰诺」不是同一个东西**） |
| 学术/药事核对 | INN "omeprazole" | 各国商品名清单 + 各国批准规格 + 规格差异 |

反例（本站**不做**的事）：不回答"我该吃几片"、不回答"能不能换成这个"、不做代购推荐。

---

## 2. 核心设计原则

**商品名不能当主键。** 它是一对多、且会碰撞的弱标识：

- 一个药 → 多国多名（商标冲突导致）：奥美拉唑 = Losec（英/北欧）/ Prilosec（美）。
- 一个名 → 多国多药，甚至同一国多配方：中国「泰诺」是复方感冒药，美国 Tylenol 是单一对乙酰氨基酚。
- 同名同药但**配比不同**：Augmentin（阿莫西林/克拉维酸）各国规格比不同。
- 同名同药但**不等效**：美托洛尔酒石酸盐 vs 琥珀酸盐。

因此：**所有查询返回的是候选集，不是唯一答案。** 唯一性由「国家 × 剂型 × 规格 × 活性成分」共同锁定。

## 3. 数据模型（四张核心表）

### L1 `substance` — 规范活性成分（全站锚点）

| 字段 | 说明 |
|---|---|
| substance_id | 稳定 slug，如 `atorvastatin` |
| inn_en / inn_zh | 国际非专利名 / 中文通用名 |
| atc | ATC 编码，如 C10AA05 |
| atc_name / class | ATC 名称、药理分类 |
| ddd | WHO 限定日剂量（数值 + 单位 + 途径），仅作参考 |

### L1b `variant` — 盐型/水合物/酯/异构体（**可替代性判定的最小单位**）

| 字段 | 说明 |
|---|---|
| variant_id | 如 `atorvastatin-calcium` |
| substance_id | 指向 L1 |
| salt_form | calcium / besylate / hydrochloride / anhydrous / hydrate / none |
| base_fraction | 盐→碱基折算系数（如苯磺酸氨氯地平 = 408.9/567.1 ≈ **0.721**，PubChem 分子量核对；早期草稿写的 0.876 是错的，2026-10 已更正） |
| interchange_note | 与同 substance 其他 variant 是否可互换 + 原因 |

### L2 `product` — 某国上市的某个具体产品（一行 = 一个国家的一个规格包装）

| 字段 | 说明 |
|---|---|
| product_id | 全局唯一 |
| country | ISO 3166-1 alpha-2（US / GB / CN） |
| variant_id | 指向 L1b |
| strength_value / strength_unit | 20 / mg；液体另存 `per_volume`（如 5 mg/5 mL） |
| dosage_form | 归一化枚举：tablet / film-coated tablet / ER tablet / capsule / oral solution / injection / cream … |
| route | oral / iv / topical / inhaled … |
| release | IR / ER / SR / GITS / none（**单独成字段，不塞进 dosage_form**） |
| pack | 包装描述（30 片/盒、100 mL/瓶） |
| mah | 上市许可持有人 |
| approval_id | NDC / PL 号 / 国药准字 |
| status + status_date | active / discontinued / withdrawn |
| source_id, source_url, retrieved_at | 可追溯性，必填 |

### L3 `name_key` + `product_name` — 名字层

`name_key` 是**归一化后的查找键**，一个 key 可挂多个 product → 碰撞就是在这里被发现的。

| 表 | 字段 |
|---|---|
| name_key | `key_id`, `norm`（归一化字符串）, `script`（latin/cyrillic/han/kana…）, `lang` |
| name_variant | `raw`（原始写法，保留 ®、大小写、空格）, `name_key_id`, `source` |
| product_name | `product_id`, `name_key_id`, `name_type`（trade / inn / old / colloquial / translit）, `is_primary` |

**碰撞分级**（由 name_key 下挂的 products 计算）：

| 级别 | 条件 | UI 表现 |
|---|---|---|
| 严重 | 不同 `substance_id` | 红色横幅："此名在中国是复方药 X，不是 Y" |
| 警告 | 同 substance，但配比/释放机制/剂型不同 | 黄色提示，列出差异项 |
| 提示 | 仅规格不同 | 规格对照表，无警告 |

### L3b `nickname` — 俗称 / 网络别名 / 旧名（只做检索入口）

昵称属于「人嘴里怎么叫」，不属于「包装上印了什么」。所以它不写进 `product_name`，也不参与碰撞：

| 字段 | 说明 |
|---|---|
| `alias` / `alias_norm` | 原写法 / 归一化键（与商品名共用同一个 `normalize()`） |
| `substance_id` | **指向成分**，不指向产品——同一个叫法在不同国家会落到不同品牌上 |
| `kind` | slang 网络俗称 · legacy 旧名 · translit 音译 · abbrev 简称 · misnomer 常见误称 |
| `confidence` | user 用户提供 · community 民间通行 · documented 旧名/药典依据 |
| `source` / `note` | 出处与解释，命中时展示给人看 |

规则：

- 只做精确 / 连写匹配，不做模糊——昵称差一个字往往就是另一个梗。
- 命中后先标「网络俗称 / 旧名」，再按成分列出各国商品名，不冒充商品名。
- 不生成同名页、不进入 `collision`：昵称不是身份，成分才是。
- **来源规则**：`source` 必填，没有来源线索的不新增。`confidence='user'` 只算线索，
  公开页标「用户提供（未证实）」；`community` 保留检索、标「社区叫法」，不冒充
  `documented`；找到独立出处后才升级。审核只能核实出处，不能代替出处。

### L3c `drug_term` — 美国街头 / 民间 / 类别叫法（v0.3）

`nickname` 要求 `substance_id` 非空，只适合「一个叫法 → 一个成分」。美国街头叫法有三类例外：

| 情形 | 例子 | 处理 |
|---|---|---|
| 类别词 | downers = 镇静剂 | `term_type='class'`，`substance_id` 为空，`examples` 给举例成分 |
| 本库无上市产品 | molly = MDMA | `substance_id` 为空，`meaning_zh/en` 说明指向 |
| 复方 | lean = 可待因 + 异丙嗪 | 同一 `term` 写两行，检索提示「可能指」 |

`alias_all` 视图把 `nickname` + `drug_term` 合成检索层唯一入口。来源与许可见 README；
ISMP 全量 LASA 清单有版权，只收 FDA 官方 tall-man 名单到 `confusable_pair`。

`confusable_pair` 存「形似/音似」药对：`name_a/name_b`、`tml_a/tml_b`（FDA 建议的
tall-man 写法）、可空的 `a/b_substance_id`（官方名单里有些药本库没有产品）、来源与日期。
成分页顶部按 `a/b_substance_id` 反查并给出警告；检索层按归一化名精确命中，不做模糊扩展。

社区 / 各国街头叫法也进 `drug_term`，但 `confidence='community'`、`country` 标来源国、
`source_url` 逐条给链接：CN 用小红书/知乎/丁香园/科普中国等公开页面，GB 用 Talk to FRANK，
AU 用 ADF，ES 用 PNSD。公开页标「社区叫法」，保留检索，不冒充 documented；没有链接的
社区叫法不新增。`drug_term` 当前 365 行：US 331、CN 13、GB 12、AU 5、ES 4。

## 4. 剂量对应：分四级，绝不越级

| 级 | 内容 | 允许输出 |
|---|---|---|
| D0 | 单位归一（mg/g/mcg/IU/mL/%/万单位、per mL vs per dose、全角） | 归一后的数值 |
| D1 | 同 variant 同剂型 → 数值直接对应 | "20 mg ↔ 20 mg" |
| D2 | 盐基折算（`base_fraction`） | "20 mg 苯磺酸氨氯地平 ≈ 17.5 mg 氨氯地平碱基" |
| D3 | 释放机制/盐型/生物利用度差异 → **不可互换** | 只给警示，**不给替代结论** |

硬规则（写进代码，不靠自觉）：

1. D3 命中时，页面上不出现任何"等量替换"表述。
2. 站点全局不输出"服用几片/几粒"。
3. 每个剂量结论必须能追到 `source_url`。

## 5. 检索与消歧

**归一化管线**（构建期索引、查询期同一套）：
`NFKC → 小写 → 去变音符/®™ → 全角转半角 → 连字符/空格折叠 → 中文繁简归一 → 尾部强度/剂型切分`

> `"Sortis 20mg"` → `{name:"sortis", strength:20, unit:"mg"}`

**打分**（返回 Top-N，永远不返回单条）：

```
name_tier:  exact 1.0 · normalized 0.95 · translit 0.90 · prefix 0.80 · trigram 0.55
score = 0.55*name_tier + 0.20*country_match + 0.15*strength_match + 0.10*form_match
```

**消歧交互**：结果页顶部给出分面筛选（国家 / 活性成分 / 规格 / 剂型），候选卡片显示 `名字 · 国家 · 成分 · 规格 · 剂型 · 置信度`。

## 6. 数据来源与授权（已核实）

**一句话结论：美国能开箱即用，英国可行，中国是硬墙——没有任何官方批量文件包含中文商品名。**

| 市场 | 有官方批量文件吗 | 含品牌名 | 能否公开再发布 | 结论 |
|---|---|---|---|---|
| 美国 | 有 | RxNorm `BN`/`SBD` + openFDA `brand_name` | 可以（政府公有领域字段，需署名） | **先做，风险最低** |
| 英国 | 有 | dm+d `AMP` 名称即含品牌 | 可以（OGL，需署名）；SNOMED CT 码另有许可 | **可行** |
| 中国 | **没有** | 无官方批量文件含商品名 | 未找到开放许可 | **本项目最大的墙** |

### 6.1 美国（P1）

| 来源 | 获取方式 | 品牌名 | 授权 | 规模 |
|---|---|---|---|---|
| RxNorm | 批量 ZIP（RRF）+ RxNav API | **有**，`SBD` = 成分+规格+剂型+品牌，正好是我们要的粒度 | 政府公有领域字段可再发布；整套 release 含 SRL-3 第三方源，**只取公有领域字段** | 活跃 SBD 9,691 / BN 5,120（2026-10） |
| openFDA NDC | API + 批量 JSON，**每日**更新 | 有（`brand_name`） | 美国政府数据 | 138,032 条（2026-10-23） |
| DailyMed | 批量 SPL XML | 有（在标签标题里） | 政府作品 | 人用处方全量约 16.8 GB |

> 关键发现：**RxNorm `SBD` 一个来源就解决了美国"品牌名 → 成分+规格+剂型"的映射**，不需要自己拼。

### 6.2 英国（P2）

- **dm+d**（NHS TRUD，每周一更新）：`AMP` 名称里带品牌名；**OGL 许可，可商用于公开展示，需署名**。
- **dm+d supplementary**：把 ATC 与 BNF 编码挂到 dm+d 产品上——这是英国拿 ATC 的实用路径（官方未背书的附属产品，覆盖不全）。
- 坑：每个 dm+d 概念都带 SNOMED CT 码，SNOMED 有独立许可，需一并处理。
- **BNF 不能用**：第三方版权（RPS），明确排除在 NICE 开放许可之外，且明确禁止抓取；非英国 IP 直接 403。MHRA 产品库只有查询页，无批量。

### 6.3 中国（P3，必须换策略）

**事实**：NMPA 药品查询、中国上市药品目录集（CDE）都是查询页，无反爬豁免；参比制剂目录是逐批 PDF 附件，商品名只有原研英文名；**国家医保目录只有通用名，没有商品名**。

**2026-10 复核（修正上一版结论）**：

- 国家医保局的「医保药品分类与代码数据库」（code.nhsa.gov.cn，每周更新）字段中**有独立的「商品名称」列**，另有 药品代码 / 注册名称 / 剂型 / 规格 / 包装 / 药品企业 / 批准文号 / 甲乙类。此前"没有任何官方批量文件含中文商品名"过于绝对。
- 但公开查询页只按「公示批次」出数：实测 `batchNumber=20220110` 可取到 1,768 行，2023 年以后的批次均返回 0。**能查 ≠ 能全量导出**，批量拿数仍要另找入口。
- 国家集采中选结果表（以上海阳光医药采购网续签表为例）只有 通用名 / 规格包装 / 生产企业 / 集采批次，**没有商品名**。
- 省级医保支付范围明细表（如天津）同时有 通用名 + 商品名 + 规格 + 批准文号，是目前最接近"官方 + 含商品名"的可下载表，但各省格式、口径、许可都不一致。

**决策：中国层不把商品名当必要条件。**

中国在售的大头是仿制药，大量产品本来就没有商品名——包装上就是「通用名 + 生产企业」。因此 CN 层的产品身份定义为：

`通用名（注册名称） + 生产企业 + 规格 + 批准文号`

其中 **批准文号（国药准字）+ 规格/包装 锁定一个产品**（实测同一批准文号常对应多个规格/包装行），商品名降级为可选别名：有则挂 `trade`，无则只挂 `inn`。检索以通用名为入口，结果按 厂家 / 规格 / 剂型 分面；跨国对应靠 substance + 规格，而不是靠品牌名对齐。

数据源优先级（CN）：

| 顺序 | 来源 | 给什么 | 定位 |
|---|---|---|---|
| 1 | 省级医保编码 / 挂网目录 | 通用名 + 厂家 + 规格 + 批准文号 + 挂网价 | 打底，覆盖在售全量 |
| 2 | 国家 / 省级集采中选表 | 通用名 + 规格 + 中标企业 + 中选价 | 在售信号 + 价格锚点 |
| 3 | NMPA 药品查询 | 通用名 + 厂家 + 规格 + 批准文号 | 抽样核对，权威 |
| 4 | 商业库（药智 / 摩熵 / 丁香园） | 商品名 + 全量 | 仅在需要商品名时采购 |

所以"抓取"在中国不是主路径。现实三条：

| 方案 | 做法 | 合规 | 覆盖 | 判断 |
|---|---|---|---|---|
| A 政府附件策展 | 省级医保编码 / 支付范围明细表（天津、北京、江苏等）是少数把**通用名 + 商品名 + 规格 + 批准文号 + 企业**放在一起的政府表格 | 无开放许可，属灰色 | 中 | **打底用**：按 通用名+厂家 口径入库，商品名能取则取 |
| B 药企官网 + 说明书 | 去 MAH 中国站找产品页与说明书 PDF，人工逐条录入 | 相对干净（只存事实 + 链原文） | **低**，且只覆盖原研 | **首选核对源**，见 6.3.1 |
| C 商业数据 | 药智网 / 摩熵 / 丁香园用药助手 | 合法 | 全 | **上线前必须解决**，否则中国栏只能标"部分覆盖" |

> 决策建议（2026-10 更新）：P3 用 A 打底——以「通用名 + 厂家 + 规格 + 批准文号」建中国产品骨架，不再要求商品名；B 只用于补原研品牌名。页面标注"中国以通用名检索，覆盖在售产品，商品名不全"；C 仅在需要商品名时采购。

#### 6.3.1 药企官网能承担什么、不能承担什么

实测（2026-10）：

- 拜耳中国「产品概览」自己写着 **"所列产品为拜耳在中国上市的部分产品"**，列表由 JS 渲染，且整页是营销内容 + 跨境电商免责声明 — https://www.bayer.com.cn/zh-cn/portfolio/products-from-a-to-z
- 阿斯利康中国直接 **CloudFront 403**，非浏览器/境外 IP 拿不到。
- 上海强生（西安杨森）站上确实有说明书 PDF，例如泰诺 酚麻美敏片说明书 — https://www.xian-janssen.com.cn/

**结论：药企官网是「核对源」，不是「覆盖源」。**

| 维度 | 药企官网 | 监管批量文件 |
|---|---|---|
| 权威性 | 高（说明书是 NMPA 核准文件） | 高 |
| 完整性 | **低**（官方自述"部分产品"） | 中–高 |
| 结构化 | 无（JS 渲染、PDF） | 有 |
| 可持续 | 差（改版、403、下架不更新） | 中 |
| 许可 | 未授权，但只存事实 + 链原文风险可控 | 部分有开放许可 |

三条使用纪律：

1. **只用于中国原研品牌的高价值补录**（top 100–200），不指望它覆盖国产仿制药商品名——而中国在售的大头恰恰是仿制药。
2. **只存结构化事实**（商品名 / 通用名 / 规格 / 剂型 / 批准文号 / 说明书 URL / 抓取日期），**不转载说明书全文**，更不转载产品宣传页（产品页属广告性质，转载可能构成发布药品广告）。
3. **每条记录允许多个佐证源**：`product` 之外加 `corroboration( product_id, source_type, url, retrieved_at )`，`source_type ∈ {regulator, mah_pdf, provincial_list, manual}`。页面显示"经 2 个来源核对"比显示"数据来自药企官网"更有说服力。

> 覆盖率的现实预期：原研品牌这条路能拿到 200–400 个中国商品名；国产仿制药的商品名（恒瑞、齐鲁、石药、正大天晴…官网基本没有产品目录）必须靠 A 或 C。


### 6.4 ATC 这一层要单独买/换

WHO ATC/DDD 索引**不允许整表复制再发布**（商用需 WHOCC 授权）。可行路径：
- 美国：RxNorm 自带的 ATC（SRL 0，可用）
- 英国：dm+d supplementary
- 中国：**官方文件里没有 ATC**，只能人工映射或购买

### 6.5 架构铁律

抓取只发生在**离线 ETL**，服务时不抓。理由：合规（尊重 robots/频率）、稳定（药监站改版不影响线上）、可复现（每次入库留快照与时间戳）。且 ETL 必须有**行数/schema 漂移告警**——反爬策略一变，字段会静默变空。

## 7. 站点结构

| 路由 | 页面 | 作用 |
|---|---|---|

技术形态建议：**静态生成 + 预构建检索索引**（SQLite 做单一真相源，构建期导出 JSON 索引与 HTML），部署到 Cloudflare Pages / GitHub Pages。理由：无服务器成本、无数据库运维、公开站被搜素引擎收录友好；将来要实时纠错只需加一个小的提交 API。

## 8. 公开站的硬约束

1. **免责与定位**：全站显著声明"信息参考，不构成用药建议，不能替代医师/药师"。
2. **覆盖度透明**：每个国家显示"已收录 N 条 / 覆盖率 X%"，并明写 **"查不到 ≠ 该药不存在"**。
3. **可追溯**：每条记录带来源与抓取日期；纠错走人工审核队列。
4. **不做广告/代购**：不出现购买链接、比价、导流。
5. **撤市药保留**：标 `withdrawn`，不删除（历史对照需要）。
6. **中国数据特殊性**：中文商品名以说明书/目录集为准；同名不同物的判定必须人工复核后才标"严重"。

**P1 的实际做法与计划不同**：openFDA NDC 目录无需账号即可批量下载（138,032 条 → 保留 110,179 条），

比走 RxNorm 的 UMLS 账号流程更快；RxNorm 留作后续补 ATC 与 SBD 精确粒度。

## 11. 已验证的跨市场碰撞（可做首页示例）

三个都核实到了原始说明书/标签，可直接用于 `/warn` 页和首页示例：

| 商品名 | 美国 | 中国/英国 | 为什么危险 |
|---|---|---|---|
| **Tylenol / 泰诺** | 对乙酰氨基酚 500 mg 单方 | 中国**泰诺** = 酚麻美敏片（对乙酰氨基酚 325 + 伪麻黄碱 30 + 右美沙芬 15 + 氯苯那敏 2 mg）；纯对乙酰氨基酚叫**泰诺林** 650 mg 缓释 | 单方止痛药 ↔ 四成分感冒药：嗜睡、升压、重复用药 |

| **Gaviscon** | 氢氧化铝 + 碳酸镁（纯抗酸） | 英国 = 海藻酸钠 + 碳酸氢钠 + 碳酸钙（藻酸盐 raft） | 活性成分集合完全不相交 |
