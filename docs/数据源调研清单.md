# 数据源调研清单（给后续 AI 复用）

> **这份文件的目的**：把「新市场/新数据源能不能入库」的调研做成**可重复调用的清单**——
> 后面的 AI 不用重新摸索，照着填、照着查、照着落证据即可。
> 每次调研完**更新本页台账**（§7）与 `docs/许可清单.md`，报告放 `reports/`。
>
> 最后更新：2026-11-20（MY 马来西亚 🟢 入库评估完成；NO/CH 🟢；KR 试试「국세청 기업회원」渠道）

## 1. 三条硬规则（先看，不满足就别继续）

1. **许可先行**：只认**产品级清单本身**的再发布许可。**「统计汇总有许可」≠「产品清单有许可」**——DE/PT 已经栽过。
2. **零付费、零伪造、零绕过**：不买数据、不绕 WAF/robots、不伪造身份、不注册需要假资料的账号。需要人工实名/人工 key 的，写「需人一句话」并停在门口。
3. **判不了就不入库**：映射不了 INN/规格/剂型的行，**丢弃 + 计数**，不猜、不硬凑。

## 2. 判定口径

| 结论 | 含义 | 动作 |
|---|---|---|
| 🟢 可入库 | 官方明确允许再发布（CC BY / CC0 / NLOD / OGL / PDL 等），产品级数据可批量 | 直接排写库窗口 |
| 🟡 需申请 / 条款不明 | 有数据但许可未写明，或需账号/书面许可 | 发申请信（§5 模板）→ 记 `docs/跟进提醒.md` → 批前只做链接层 |
| 🔴 不可 | 明确禁止再发布、无批量入口、或只有页面无数据 | 只做「官方查询入口 + 署名」链接层，不计条数 |

## 3. 每个数据源必查 12 项（逐项填，缺一项写「查不到 + 原因」）

1. **官方入口 URL**（数据集页 + 文件直链）
2. **许可原文 URL + 许可名称**（CC BY 4.0 / NLOD 2.0 / OGL v3 / PDL 1.0 / 自定义）
3. **再发布限制**：允许商用？允许演绎？要求署名格式？禁止批量抓取？
4. **是否需账号**：免账号 / 免费注册 / 需本国手机实名 / 需人工审批 key
5. **批量入口形态**：CSV / ZIP / XML / REST API / 只能逐页查询
6. **字段清单**：商品名、活性成分+含量、剂型、规格、MAH、注册号、状态、日期
7. **条数**（实测，不是估计）
8. **更新频率 / 数据截止日**
9. **规格与剂型可得性**：结构化列 / 需从名称解析（写明解析成功率）
10. **署名要求原文**（写进 About / 覆盖页 / datapackage）
11. **抓取礼貌**：robots、频率限制、是否需 UA 标识
12. **入库成本**：人时估算 + 主要风险（许可/字段/映射）

## 4. 证据与落盘规则

- 报告：`reports/YYYY-MM-DD-<market>-<主题>.md`，结论先行、每个结论附**官方 URL + 抓取日期**。
- 原始数据：`data/raw/<market>/`（抓取缓存，不入库）。
- 小快照 + 许可说明：`data/sources/<market>_<数据集>_<日期>.license.md`（进仓库）。
- 许可台账：更新 `docs/许可清单.md`（原有格式，不另起一套）。
- 计数口径：一律 `db/q.py` 现查，不照抄旧数字。

## 5. 申请信模板（🟡 时用；用户 2026-11-20 授权：可由 agent 用 SMC 邮箱自助发送）

**收件人**：该机构数据/许可部门官方邮箱（从官网「联系我们 / 版权 / 数据使用」页找）。
**主题**：`Request for permission to re-use <dataset name> (product-level list)`

```
Dear <Agency> team,

We operate a non-commercial reference site (https://drugcrossref.com/) that helps users
identify a medicine by its brand name across countries — identity mapping only, no dosing
advice and no substitution recommendations.

We would like to re-use the product-level dataset "<dataset name>" published at
<dataset URL> (licence: <licence or "not stated">) to add <country> to our cross-reference.

Specifically we would store only factual fields — brand name, active ingredient(s) and
strength, dosage form, marketing-authorisation holder, registration number, status and
dates — with clear attribution to <Agency> and the dataset's last-update date.

Could you confirm (a) whether re-distribution of these factual fields is permitted,
(b) the required attribution wording, and (c) whether a bulk download (CSV/API) is available?

Thank you for your time.

Best regards,
<name / organisation>
<email>
```

发送后：`docs/跟进提醒.md` 记节点（首查 +1 周、复审 +1 月），状态写「已发送（无退信；未确认受理）」。

## 6. 韩国 KR：已试过的路 + 「국세청 기업회원」渠道（2026-11-20 新增）

- **已确认卡点**：`data.go.kr` 个人会员需**韩国手机实名**；`data.mfds.go.kr` 文件版同样强制韩国实名（韩国信用信息局 + KG Mobilians）——「只要邮箱」的口子不存在（证据 `reports/2026-11-18-kr-data-source-scan.md`、`reports/2026-11-19-kr-account-free-sources.md`）。
- **新线索（用户 2026-11-20 截图）**：登录页有 **「기업회원 / 국세청에 등록된 사업자」**（企业会员：国税厅登记的事业者）入口。若 SMC 在韩国有**事业者登录号**且能通过国税厅身份验证，理论上可绕过个人手机实名。
- **待验证清单**（下一次开工按这个查）：
  1. 该入口属于哪个站点（data.go.kr？data.mfds.go.kr？），URL 记下来；
  2. 企业会员注册需要：事业者登录号 / 法人编号 / 国税厅 ID / 公认认证书（공동인증서）/ 短信；
  3. 是否允许**非韩国法人**注册（SMC 的注册地）；
  4. 注册后能否下载 `15095677`（의약품 제품 허가정보）或 `data.mfds.go.kr` 文件版；
  5. 若需要人工证件/认证书 → 写「需人一句话」，不硬闯。
- **邮箱**：用户指定用 **SMC 邮箱**发申请（凭据不进仓库；浏览器登录态由人提供）。
