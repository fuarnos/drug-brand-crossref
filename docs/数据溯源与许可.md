# 数据溯源与许可（provenance & licensing）

> 2026-10-30（task-26）｜ 本文回答三件事：**每条数据从哪来、用什么方法定的、能不能对外发**。
> 相关文件：[docs/许可清单.md](许可清单.md)（逐来源许可结论）、[LICENSE](../LICENSE)（代码 MIT）、
> [AGENTS.md](../AGENTS.md)（数据纪律）、schema 的溯源列（`substance` / `brand_family`）。

---

## 0. 结论（先看这段）

1. **代码 MIT，数据不随代码许可**：数据按来源逐个判定再发布条件；对外只发**派生层**
   （站点页面、检索索引、聚合 CSV），**不整包分发**受限来源的原始文件。
2. **溯源 = 可核查的「来源 + 方法 + 置信度 + 时间」，不是「人工复核」**：本项目是纯 AI 项目，
   `method='rule' / 'multi-source'` 表示**规则自动定案 + 多源交叉**，`editorial` 只表示
   「来自人工种子文件（逐条有出处）」，**都不等于逐条人工审核**。
3. **旧数据不伪造溯源**：task-26 迁移前的行四列保持 `NULL` =「来源未记录」；只有
   `brand_family`（100% 人工种子表）回填 `editorial / manual_seed / high`。
4. **受限来源清单**（见 §4）：CN NHSA、ES CIMA、MX COFEPRIS、TGA CMI / ARTG 明细层等，
   导出时标 `non_redistributable` 或只做聚合，不提供原始整包。

## 1. 溯源字段（schema）

| 表 | 列 | 语义 |
|---|---|---|
| `substance`（成分主名） | `source_id` | 主名/合并决策的主来源（对应 `source.source_id`） |
| | `method` | `rule`（规则推导）/ `multi-source`（≥2 源一致）/ `editorial`（人工种子文件）/ `imported`（来源直接导入） |
| | `confidence` | `high` / `medium` / `low` / `unknown` |
| | `decided_at` | 决策时间（ISO8601 UTC），不是抓取时间 |
| `brand_family`（品牌家族，唯一人工表） | 同上 4 列 | 全部 `editorial / manual_seed / high`（种子文件 `data/seed_families.py`） |

- **写入入口**：`etl/provenance.py` 的 `mark_substance()` / `mark_family()`：
  **空才写**、按强度提升（`editorial > multi-source > rule > imported`）、**同级不覆盖**（保留最早决策）。
- **批次级溯源**（已有）：`source`（license/license_url/data_as_of）与 `ingest_run`
  （每批 rows_in/kept/时间）——回答「这批数据哪来的」；上面的 4 列回答「这条主名谁定的」。
- 查询示例：

```sql
SELECT method, confidence, COUNT(*) FROM substance GROUP BY 1,2 ORDER BY 3 DESC;
SELECT source_id, COUNT(*) FROM substance WHERE source_id IS NOT NULL GROUP BY 1;
SELECT * FROM brand_family;   -- 4 行，全部 editorial/manual_seed/high
```

- 映射候选 CSV（`data/cross_market_*`、`combo_match_candidates`、`cn/es_inn_overrides`、
  `tw_ingredient_aliases`、`inn_zh_backfill_v2`）带 `confidence`，并在后续批次补
  `source_id` / `method` / `decided_at`（task-26 已定列，生成脚本同批更新）。

## 3. 「对外只发派生层」策略

| 层 | 内容 | 是否对外 |
|---|---|---|
| 代码 | `etl/ db/ lib/ site/ mobile/ tests/` 等 | ✅ MIT |
| 派生数据 | 站点页面 / `site/dist/` 的索引与页面、`coverage` 聚合、`datapackage` 元数据 | ✅ 按来源署名 |
| 小快照 | `data/sources/`（人工维护的小型派生/种子文件） | ✅ 随仓库 |
| 原始缓存 | `data/raw/`（大文件、受限来源原文） | ❌ 不入库、不对外（gitignore） |
| 数据库 | `data/drugs.db`（可重建） | ❌ 不入库 |
| 受限来源整包 | NHSA 原始 PDF/CSV、CIMA 明细、COFEPRIS 原始目录、TGA CMI 正文等 | ❌ **不整包分发**；站点只展示事实字段 + 链接 |

- `datapackage.json`（由 `site/build.py` 生成）应包含：来源清单 + 许可 + `non_redistributable` 标记
  + 「规则自动定案 + 多源交叉 ≠ 人工复核」声明（**build 侧实现**，数据侧提供字段与文案）。
- 页面署名规则：每国数据页/About 页署名来源与数据截止日，并链回官方页面；不暗示官方背书。

## 5. 维护流程（新增数据源 / 方法变更）

1. 先查许可 → 写 [docs/许可清单.md](许可清单.md)（结论 + 义务 + 证据 URL + 再发布范围）；
2. ETL 只存事实字段；原始缓存进 `data/raw/`（不入库）；
3. 新写入的 `substance` / `brand_family` 调 `etl/provenance.py` 打 `source_id/method/confidence/decided_at`；
4. 规则/映射产物（CSV）保留 `evidence` / `confidence`，补 `source_id/method/decided_at`；
5. 更新 `data/sources/drift-baseline.json`（`etl/drift_check.py --write-baseline --force`，维护者批准）；
6. 站点/About/`datapackage` 同步署名与 `non_redistributable` 标记；四语同步；
7. 迁移类改动：先备份 → 副本验证 → `db/init_db.py` 幂等迁移 → `db/check_data.py` + quick/FK → 记录报告。
