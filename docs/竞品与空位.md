# 竞品与空位

> 问题：这个站要做的事（商品名 → 成分/规格 → 他国对应产品），有没有人已经做了？
> 结论：**有，而且不止一层。** 消费级 App 已经做掉了「品牌名跨国对应」这件事的主体；
> 但「同名不同药」「同名不同规格/释放机制」这两层，目前没有产品把它当功能。
> 调研时间：2026-10-25。带「待核实」的条目是没拿到一手页面、只凭检索摘要。

---

## 1. 一句话回答

- **直接竞品**：2 款手机 App（World Drugs Converter、MedMatch Pro），核心流程与本站立项时写的一模一样：选「从哪国 → 到哪国」，给当地商品名。
- **参考级老产品**：Martindale、Lexicomp、Index Nominum、WHODrug —— 做的正是「各国商品名索引」，但形态是书/订阅库/申报词典，不是免费网页。
- **免费原料**：Drugs.com 的 International 库，只做了单向（商品名 → 成分 → 哪些国家有），回答不了「那我在英国该买什么」。
- **标准层**：IDMP 的 PhPID 就是官方定义的「同一个药品」（成分+规格+剂型，跨品牌跨国），欧盟跨境电子处方已经在用。
- **中国侧**：原研汇、进口原研药目录这类小项目做过「原研药 + 商品名」，但只覆盖中国、只到品种级、且大多停更。

**空位不在「跨国对应」，在「对应的可信度」和「同名不等于同药」这件事上。**

对公益项目来说，这些产品不是对手，是互补：它们做入口，本站做原料和警示。

## 2. 直接竞品（消费级，功能重合最高）

| | World Drugs Converter | MedMatch Pro |
|---|---|---|
| 开发者 | TenTal（tental.net） | Serhii Kaduchenko / MedMatch Pro Inc. |
| 平台 | iOS + Android | iOS（Android 标「coming soon」） |
| 覆盖 | 200+ 国家/地区，约 200 万条产品名，约 1 万个分子 | 70+ 国家 |
| 输入 | 商品名 / 成分（molecule）/ ATC | 商品名 / 处方拍照 OCR / 药片与包装拍照 |
| 输出 | 「From → To」国家，当地等价产品名，可全屏放大给药师看 | 当地商品名 + 成分 + **剂量** + 可得性 |
| 离线 | 是（约 193 MB 本地库） | 部分（收藏可离线） |
| 收费 | 免费=只搜商品名；Pro=常规药等价；Premium=特殊药+分子+ATC | 免费、无广告、无账号 |
| 数据来源 | 「由一位执业药师整理」，无逐条溯源 | 未说明 |
| 附加 | 收藏、最近路线、分享链接 | 用药提醒、说明书翻译 |

两款都把「旅行/外派/慢病带药」当主场景，都用「给药师看屏幕」这个交互。**这正是本站立项文档里的场景 1。**

需要注意的两点：
- World Drugs 的示例场景直接写的就是「出差到中国，怎么问当地药名」——**它把中国算在覆盖里**，但中国数据从哪来、质量如何，描述里没写（待核实）。
- 两款的功能描述里都**没有**「同名不同药」的提示，也没有「这条对应关系出自哪份批准记录」。它们的免责声明反而在说「数据库可能有错或过期」。

## 3. 参考级 / 专业级（同一件事，不同形态）

| 产品 | 形态 | 覆盖 | 关键字段 | 与本站的关系 |
|---|---|---|---|---|
| **Martindale: The Complete Drug Reference**（Pharmaceutical Press；经 MedicinesComplete / UpToDate Lexidrug 访问） | 订阅参考书/库，季度更新 | 5,500+ 专论、6 万条制剂、9 万条商标名、32 国、10,900+ 厂商（第 36 版口径，据药智说明页） | 可按**国家**浏览制剂；商品名 → 成分；含 Synonyms / BAN / INN | **功能上就是本站的「参考版」**：查 Seguril(Spain) → 呋塞米。无 API、收费、条目是否带规格待核实 |
| **药智网「马丁代尔大药典」库** | 中文 Web，VIP | 同上 | 商标名 + 厂商国别缩写 + 活性成分 + 适应症（中/英）；制剂检索仅 VIP | 说明国内**有人愿意为「外国商品名查成分」付费** |
| **Lexicomp（UpToDate Lexidrug）** | 订阅临床库 | 各国 | 每条专论有 **International Brand Names** 字段 | 临床药师的标准做法，证明需求真实存在 |
| **Index Nominum** | 老牌国际药名目录，现见 DrugBasePlus 收录 | 多国品牌名 | 商品名 ↔ 成分 | 历史权威；在售状态与覆盖待核实 |
| **WHODrug Global**（Uppsala Monitoring Centre） | B2B 词典，半年一版，CSV | 近 150 国 | 商品名 + 上市许可持有人 + ATC + 成分；有中文版 | 行业标准：FDA 要求 2019-03-15 后启动的研究用它编码。**证明「跨国商品名」是可以做成数据生意的** |
| **Cortellis / AdisInsight / 摩熵·药融云** | B2B 情报库 | 全球 | 各国上市状态、商品名 | 面向注册与立项，不面向「我手上这盒是什么」 |

> 欧盟的**平行进口**行业是同一需求的 B2B 版本：把 A 国批准的品牌药映射到 B 国同成分同规格的产品上，靠的是各家自建库，且有专门研究算它省了多少钱。这说明「同成分同规格的跨国对应」是有商业价值的，只是从没做成公开产品。

## 4. 免费/公开的原料层

| 来源 | 能回答 | 不能回答 |
|---|---|---|
| **Drugs.com International** | 输入外国商品名（如 Dexivant）→ 成分（右兰索拉唑）→ 在哪些国家（墨西哥） | 反向：「我在英国该买什么」；规格；同名碰撞。美国已有的品牌会直接跳到美国专论页，不走国际库 |
| **各国官方库**（openFDA NDC / dm+d / COFEPRIS / NMPA+医保代码） | 本国商品名 + 规格 + 批准记录 | 跨国对应（这正是本站在补的那一层） |
| **Wikipedia / Wikidata** | 常见药的商品名清单 | 系统性、规格级、可溯源 |
| **FDA Orange Book（TE 码）** | 美国境内仿制药可替代性 | 跨国 |
| **dm+d 的 VMP** | 英国境内「同成分同规格」的虚拟产品层级 | 跨国 |

一句话：**原料是公开的，把原料缝成「跨国对应」的那层是各家自己做的**——这也解释了为什么市面上的产品要么收费，要么黑盒。

## 5. 标准层：官方其实定义过这件事

**IDMP 的 PhPID（Pharmaceutical Product Identifier）** 的定义就是「活性成分 + 规格 + 剂型」，**不含品牌、不含包装、不含国家**。也就是说：PhPID 相同的两个产品，就是「同一个药」。

- 欧盟跨境电子处方（ePrescription / eDispensation，MyHealth@EU）就是按这套标识在 A 国开方、B 国调剂；
- FDA 与 Global IDMP Working Group 在推全球落地。

**本站在做的事，等于给美/英/中/墨手工实现了一个 mini-PhPID**，只是没沿用那个名字。这有两个用处：
1. 说明方向不是臆想，是监管层认的抽象；
2. 将来若要接 IDMP/SPOR，现在的 `substance + variant + 剂型 + 规格` 就是天然对接口。

## 6. 中国侧已经有的小产品

| 产品 | 做了什么 | 局限 |
|---|---|---|
| **原研汇**（微信小程序，2025-02） | 搜通用名/商品名/厂商，按疾病分类，NMPA 数据，约 400–900 条 | 只有中国、只到品种级；V2EX 评论已指出商品名标错；2026-09 有「项目变成诗文了」的反馈，疑似停更 |
| **进口原研药目录**（medicine.lvwzhen.com，开源） | 约 400 种进口原研药，通用名/商品名/厂家/图片，GitHub 可纠错 | 同上；无规格、无跨国 |
| **用药助手 / 药智 / 摩熵** | 国内说明书、医保、注册数据 | 以中国为主，跨国商品名不是卖点 |
| **Payke / 集匠**（日本） | 扫日本药妆条码 → 中文商品信息 | 只日本、只 OTC/药妆，解决「这是啥」不解决「对应哪个」 |

这一层的信息量在于：**国内已经有人反复尝试，但都停在「品种级 + 单国」**，没人往「规格级 + 跨国」走。

## 7. 公益项目该怎么看这些产品

先说清楚：**这不是竞争关系。**

- 两款 App 是黑盒 + 订阅，本站是公开 + 可溯源 + 免费。公共品和商业品在同一个问题上并存是常态（Wikipedia / Britannica、OSM / Google Maps），不需要「打赢」，也不需要把国家数从 4 补到 200。
- 它们证明了两件事，对公益项目都是好消息：需求是真的；而且**没人做「这个名字在那边其实是另一个药」**——这恰好最适合非商业方来做，因为说「不能换」没有收入。
- 公益项目的失败模式不是被抢用户，是**没人接手就烂掉**。所以标准从「可防御」换成「可交接」。

三个自检，比「差异化」更贴题：

1. **可核查** — 每条结论点得回批准记录（NDC / dm+d / COFEPRIS 注册号）。这是本站唯一比 App 硬的地方，也最好做。
2. **可复用** — 数据能整包下载、许可证写清楚，别人（包括那两款 App）拿去用不欠人情。公益项目的产出应该是原料，不是入口。
3. **可交接** — 建站、ETL、schema 都在仓库里，懂 Python 的人接手能跑起来；README 已经做到大半。

以及一条已经在守的底线：不给服药方案、不猜规格、查不到就说查不到。

### 具体一点：谁覆盖什么

| | App 有 | 本站有 |
|---|---|---|
| 国家广度 | 200+ / 70+ | 4 |
| 规格 + 释放机制 | 不保证 | `variant` + 碰撞分级 |
| 同名不同药警示 | 无 | 14,871 页 |
| 每条可溯源 | 无 | 有 |
| 开放下载 | 无 | 可做 |
| 收费 | 订阅 | 无 |

不重叠的那三行，就是公益项目该站的位置。

## 8. 三种做法（不冲突）

| 做法 | 说明 |
|---|---|
| **核对页** | 免费网页，碰撞页当入口。现有 MVP 就是这个形状，继续做 |
| **开放数据集 / API** | 公益项目最该产出的东西；App 是渠道，不是对手 |
| **「同名不同药」警示库** | 范围最小、最不容易出错、最不需要持续扩国家 |

不需要选一个放弃另外两个：网页是展示，数据集是产出，警示库是核心内容。

## 9. 下一步：四件核对小事（都是几十分钟的量）

1. 装 **World Drugs Converter**（免费档）+ **MedMatch Pro**，只用三个 case 试：`泰诺`、`Benadryl`、`Panadol`。
   看它给不给中国结果、给不给英国 Benadryl、有没有把「泰诺 ≠ Tylenol」说出来。
2. 查 World Drugs 的中国数据来自哪里（应用内「关于/数据来源」页）。若来自公开库，说明中国层能靠公开数据做到什么程度，可作参考。
3. 找一家有 Martindale 访问权的渠道（NHS/高校/药智试用），核一条 `Seguril` 与一条 `Augmentin`，确认制剂条目**是否带规格**——这决定「规格级」是不是真空位。
4. 用 dm+d 的 VMP 反查本站 `variant` 的覆盖率：如果 VMP 能自动生成「成分+规格+剂型」三元组，本站的 61,051 条英国数据可以直接变成 PhPID 风格的锚点。
