## 7. 环境 / 测试 / 发布流程 / 红线

- **环境**：Windows + PowerShell，仓库根 `D:\同种药物商品名剂量对应网站`；Python 用
  `C:\Users\asus\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`（下称 `$py`）；git 用 `tools\git\cmd\git.exe`（不在 PATH）；无 CI，本地测试即门槛。
- **测试**（改哪层跑哪层，发布前全跑）：
  ```powershell
  & $py -m unittest discover -s etl -t etl
  & $py -m unittest discover -s lib -t lib
  & $py -m unittest tests.test_mobile_inbox -v
  & $py tests/trilingual/run_tests.py          # 三语/繁中检索一致性（只读 DB）
  ```
- **发布流程**（唯一入口；发布经理 index-p1 执行，文档/其他角色不发布）：
  1) `CHANGELOG.md` 顶部加 `## vX.Y.Z — YYYY-MM-DD`（2–5 条用户可感知变化）；
  2) `& $py site/build.py` 等到 `== done ==`（**同一时间只允许一个会话跑**）；
  3) `& .\deploy\publish.ps1`（增量 gh-pages；`-FullPush` 可回退全量；失败保留临时目录/自动回滚）；
  4) `& $py deploy/verify_live.py --expect-version vX.Y.Z`（smoke，含首页/页脚/whats-new/core/About/GoatCounter）；
  5) `git tag -a` + push main/tag + `python deploy/github_release.py --tag --name`（Release 正文用 CHANGELOG 节）。

## 13. 上一个 Lead 的工作方式（用户要求告诉新对话）

1. **Lead 只做沟通/决策/验收**：不写代码、不构建、不发布、不写库；每个执行动作都分给 agent；Lead 对用户负责。
2. **团队分工**（本 workspace 实例）：
   - `index-p1` 发布经理（**唯一** publish/git tag/Release 执行者）；
   - `impl-lazyload` 功能（**build.py 唯一写者**，任务串行）；
   - `data-depth` 数据/DB 窗口；
   - `cn-mapping` CN 数据；
   - `dose-impl` 清洗/ETL；
   - `index-perf` 搜索/lib/评测；
   - `impl-mx-atc` ATC/市场审计；
   - `dose-mapping` 文档/队列/早报/metrics/看板（本文档作者）。
3. **任务板**：`team_task_create` 必须带 **write scopes**；有先后依赖用 `blocked_by`（serial）；流程 **claim → 做 → complete**；回 Lead 报告 **≤250 字**；工作区 `reports/` 是事实源；纯 AI 项目**不等人工审核**（判不了的丢弃并计数）。
4. **版本循环**：`CHANGELOG.md` 顶部加节 → 全量构建到 `== done ==` → `deploy/publish.ps1` 增量发布 → `verify_live.py --expect-version` smoke → tag/push → GitHub Release → 把数字（版本/commit/tag/gh-pages/文件数/体积/smoke/增量）汇报给 Lead。**build.py 发布构建期间冻结**（其他 agent 不得改）；**绝不手工推 gh-pages**。
5. **并行原则**：数据/审计/报告可并行（3–5 agents）；**build.py 与 publish 串行**；各 agent 写范围不重叠（冲突用 `blocked_by`/消息协调）。
6. **红线**：不做用药建议/剂量换算/可替代判断；**品牌名永不机器翻译**；**不付费买数据**（不询价商业 API）；**不绕 WAF/验证码/反爬**；DB 写窗口必须备份/回滚清单/hash/check/VACUUM；**删除前快照**。
7. **沟通与 bug 处理**：用户报 bug 时 **截图 → 复现 → 建任务 → 下版修复 → 线上验证**；Lead 有决策权：**P0 立即修、P1 下批、P2 backlog**，不逐项问用户。
8. **定时**：会话级 schedule 不继承；按 **§12** 只重建 **2 条 cron**（00:35 开工 / 08:20 收尾）；政府申请**不单设 at 节点**，每日开工按 `docs/跟进提醒.md` 核对（到期/逾期才处理）。
9. **文档与提交**：队列/早报/审计/交接保持最新；提交按主题分组；**切会话前工作树保持 CLEAN**（提交/清理由发布经理/Lead 协调，文档岗不 commit）。
