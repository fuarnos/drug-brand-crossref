## 4. name 页 −517 归因：数据导致，不是构建不确定

**结论：是 FR 写库（v1/v3）导致，不是构建不确定性问题。** 任务 5 的代码改动只涉及资源引用/哈希/FR 文案，
`git diff site/build.py` 没有触及 `load_index()`、`worth_page`、name 页生成逻辑。

证据（只读 SQL，517 个消失页的 slug 全部能反查到 key_id，517/517 匹配）：

- 这 517 个 key 在**新旧库里都是**：`n_prod=1`（单产品）、`countries=FR`、`trade=1`；
- 唯一变化的输入是**成分映射**：`n_sub` 变化 466 个（旧库 `n_sub=0`，新库 `n_sub≥1`），其余 51 个输入完全相同；
  `n_prod / countries / trade` 变化 **0**；
- 机制：旧库这些 FR 产品的 component 没有落到 `variant`（`LEFT JOIN variant` 后 `sid=NULL`）→ `load_index` 里
  `a["sids"]` 为空 → 走「名称层无成分」豁免（`single_ok = n>=2 or not a["sids"] or 市场∈{CN,TW,ES,MX}`），所以建页；
  FR v1/v3 把这些成分映射成功后 `sids` 非空、`n=1`、市场 FR（不在单包装白名单）→ `single_ok=False`、`level` 回落到
  `info` → `worth_page=False`，页面不再生成。
- 影响：**v0.11.4 线上这 517 个 FR 单产品商品名页在 v0.11.5 会消失（404）**，sitemap 同步减少。
  这是「FR 成分映射提升」的副作用，产品口径要人拍板：
  ① 接受（FR 产品仍能从成分页/品牌页进入）；② 把 FR 加进 `SINGLE_NAME_PAGE_MARKETS`（会多建约 1,900 个 FR 单包装页，dist +~8 MB）；
  ③ 保留旧 URL → 301 到成分页（需要构建期 extra sitemap/redirect 支持，工作量最大）。
  **本任务未擅自改白名单**，请 Lead 在最终构建前定口径。

## 7. task-8 补修：首页 app.js / bilingual.js 的版本参数（verify_live 门槛）

### 7.1 为什么这处**必须**带版本号

`app.js` / `bilingual.js` 是**稳定文件名**（内容随 `BUILD_V` 变，构建期注入搜索索引版本），
首页是唯一引用点（`load` 后动态注入）。裸 URL 的后果：

1. 浏览器按完整 URL 缓存 → 发布新 `app.js` 后用户仍跑旧版首页搜索逻辑（数据版本参数过期）；
2. `deploy/verify_live.py` 的 `homepage-appjs` 守卫要求首页 HTML 里存在
   `assets/app.js?v=<数字>`，裸 URL 直接 **1 failure**。

与 task-5 修掉的相反：CSS/boot 是**内容哈希文件名**（不可变 → 不加 `?v`），
app/bilingual 是**稳定名 + 可变内容**（→ 必须加 `?v=BUILD_V`）。

### 7.2 三处改动（+1 处死代码防御）

```diff
# 1) _optimize_home_html()：首页 load 后注入 app.js
- + f"var s=document.createElement('script');s.src='{prefix}assets/app.js';"
+ + f"var s=document.createElement('script');s.src='{prefix}assets/app.js?v={BUILD_V}';"
# 2) 同处：bilingual.js
- + f"var b=document.createElement('script');b.src='{prefix}assets/bilingual.js';"
+ + f"var b=document.createElement('script');b.src='{prefix}assets/bilingual.js?v={BUILD_V}';"
# 3) boot.js：长尾页 load 后注入 bilingual.js
- "b.src=r+'assets/bilingual.js';document.body.appendChild(b);};"
+ "b.src=r+'assets/bilingual.js?v=__BUILD_V__';document.body.appendChild(b);};"
# 4) _app_boot()（防御，见 7.3）：app.js 也带版本号
- 's.src="' + prefix + 'assets/app.js";'
+ f's.src="{prefix}assets/app.js?v={BUILD_V}";'
```

未动：CSS/boot 的哈希名 + 无 `?v`；`i18n.*.js` 原有 `?v=BUILD_V`；`app.js`/`atc4.js` 稳定文件名。

### 7.3 死代码说明（Lead 问 L10654-10659 / L10854）

- `_app_boot()` 与 `.replace("{APP_BOOT}", _app_boot(prefix))`：首页模板里**没有** `{APP_BOOT}` 占位，
  该 replace 空转；现产物 5 个首页的 app.js 全部来自 `_optimize_home_html` 的注入。
- L10854 `<script defer src="{{prefix}}assets/app.js">`：5 个首页产物里都**不出现**该标签
  （实测 `index.html` / `es|zh|fr|zh-hant/index.html` 均无 `defer … assets/app.js`，也无 `{assets` 残片）。
- 两处按「防御性同口径」处理：`_app_boot` 加 `?v={BUILD_V}` 并注明；L10854 保留原样（不影响产物），
  若以后有人把它接回模板，应改走 `_optimize_home_html` 的注入路径。
