### 4.3 防遮蔽：审计的假设需要修正一处

审计 §3.4-4 说「`antibiotic` 同时是 `name_key`」。现查确认，但**机制比审计写的更松**：

- `name_key.norm='antibiotic'` 确实存在，`key_id='antibiotic'` 下挂着 **7 个 active 产品**
  （US/CA 的 OTC 复方抗菌软膏：Neomycin / Bacitracin Zinc / Polymyxin B / Gramicidin）。
- **但客户端的别名/俗称层排在药名检索之前，`antibiotic` 已经是 `data/aliases.json` 里的
  俗称条目**（`{"a":"antibiotic","v":null,"i":"Antibiotics","k":"folk"}`，指「抗生素」这一
  类别说法、不指向任何成分）。所以今天搜 `antibiotic` 得到的是「民间叫法」说明，**不是**
  那 7 个软膏商品名。
- 结论：把 `antibiotic` 并进 `categories.json` 的 aliases **不会**藏掉商品名结果，而会把
  今天那句「民间叫法」换成整类候选集——两种都说得通，但会**改变俗称层语义**。

采用的规则（比「删词」保守，比「客户端加特判」省事）：

| 撞车形态 | 处理 | 依据 |
|---|---|---|
| **全等** `name_key.norm` | 登记进 `NAME_KEY_SHADOW_EXCEPTIONS`（现只有 `antibiotic`），**不并进客户端 aliases**，lib 的 `match_category()` 也不认它 | 全等命中是最强的名字结果，不许被大类静默替换 |
| **名字包含**命中 | 允许大类接管 | 产品意图：几条噪音 → 整类候选集 |
| 新的全等撞车 | `assert_no_unlisted_shadow(db)` 抛 `ValueError`，**构建报错**（比线上遮蔽好） | 单测 `test_no_unlisted_shadow` 每次跑 |

发布说明要写）：

## 7. #1 构建期类别索引：规格 + 原型实测

### 7.1 产物规格（三个文件）

```
site/dist/data/idx/cats.json        词表 + 16 类元数据 + ATC4 码 + 成分总量 + 1,154 个 atc_codes
site/dist/data/idx/cat-<id>.json    每类 top200 结果切片（16 个，字段见下）
site/dist/data/idx/atc-ing.json     ATC 类别码 → 成分 + active 产品数（ATC 码查询的成分摘要）
```

`cats.json`（原型实际内容，`v` = 构建版本号）：

```jsonc
{
  "v": "3973462234",
  "words": {"退烧药": "cat:analgesics", "bloodpressuremedicines": "cat:antihypertensives", …},
  "cats": [{
    "id": "analgesics", "url": "cat/analgesics.html",
    "prefixes": ["N02", "M01A"],
    "labels": {"en": "…", "es": "…", "zh": "…", "zh-Hant": "…"},
    "atc4": ["M01A", "N02A", "N02B", "N02C"],
    "ing": [["Acetaminophen", 10002], ["Ibuprofen", 3216], …],   // top16，排序 + 首屏成分预览
    "slice": {"f": "data/idx/cat-analgesics.json", "n": 200}
  }, …],
  "atc_codes": ["A", "A01", …]        // 1,154 个，替代 categories.json 里的同名字段
}
```

与审计原案的两处差别（都是为了更小更好用）：

1. **`words` 只放类别词（125 个），不放 ATC 码**。客户端 `render()` 本来就用正则
   `atcQuery()` 先认码，码表放 `atc-ing.json` 的 key 里即可 → 省约 7 KB，也不用枚举 1,154 个码。

### 8.2 `#1` 新增生成函数（**已落地**，本会话原型版，参考）

```python
# ── v0.10.3 #1：构建期预生成类别索引（首查不再等 41 MB 的 core.json）──────────
# 产物：data/idx/cats.json（词表 + 16 类元数据）、data/idx/cat-<id>.json（每类 top200 切片）、
#       data/idx/atc-ing.json（ATC 类别码 → 成分摘要）。
# 全部派生自 CONSUMER_CATEGORIES + COLLOQUIAL_ALIASES + entries + DB，不引入人工标注；
# 切片里仍是候选条目，商品名仍然不是主键（页面文案不变）。
CAT_SLICE_FIELDS = ("k", "d", "u", "c", "x", "s", "f", "n", "atc", "v", "vs", "l")
CAT_SLICE_TOP = 200
ATC_ING_LEVELS = (1, 3, 4, 5)   # ATC 层级前缀长度：L1=1 / L2=3 / L3=4 / L4=5（7 位 L5 走老路径）
ATC_ING_TOP = 5


def _cat_norm(s: str) -> str:
    """与客户端 _catNorm() 同口径：NFKD 去重音 + 去空白 + 小写。"""
    t = unicodedata.normalize("NFKD", str(s or ""))
    t = "".join(ch for ch in t if not unicodedata.combining(ch))
    return re.sub(r"\s+", "", t).lower()


def _ing_totals(db: sqlite3.Connection, prefixes: list[str]) -> list[tuple[str, int]]:
    """成分在本类别内的 active 产品数（降序）；与 lib/search.py `_ingredient_totals` 同口径。"""
    prefixes = [p for p in prefixes if p]
    if not prefixes:
        return []
    cond = " OR ".join("s.atc LIKE ?" for _ in prefixes)
    rows = db.execute(
        f"""SELECT s.inn_en AS inn, COUNT(DISTINCT p.product_id) AS n
            FROM substance s JOIN variant v ON v.substance_id = s.substance_id
            JOIN product_component pc ON pc.variant_id = v.variant_id
            JOIN product p ON p.product_id = pc.product_id AND p.status = 'active'
            WHERE s.atc IS NOT NULL AND ({cond})
            GROUP BY s.substance_id ORDER BY n DESC""",
        tuple(p + "%" for p in prefixes)).fetchall()
    out: dict[str, int] = {}
    for inn, n in rows:
        if inn:
            out[inn] = max(out.get(inn, 0), int(n or 0))
    return sorted(out.items(), key=lambda kv: -kv[1])


def _atc4_of(db: sqlite3.Connection, prefixes: list[str]) -> list[str]:
    """该大类实际覆盖到的 ATC 4 位码（现查，不用手工表）。"""
    cond = " OR ".join("s.atc LIKE ?" for _ in prefixes)
    return sorted({r[0][:4] for r in db.execute(
        f"SELECT DISTINCT s.atc FROM substance s WHERE s.atc IS NOT NULL AND ({cond})",
        tuple(p + "%" for p in prefixes)) if r[0]})


def _atc_ing_map(db: sqlite3.Connection) -> dict[str, list[list]]:
    """ATC 类别码 → [[成分, active 产品数], ...]（一次 join，再按 ATC 层级前缀聚合）。"""
    exact: dict[str, dict[str, int]] = {}
    for atc, inn, n in db.execute(
            """SELECT s.atc AS atc, s.inn_en AS inn, COUNT(DISTINCT p.product_id) AS n
               FROM substance s JOIN variant v ON v.substance_id = s.substance_id
               JOIN product_component pc ON pc.variant_id = v.variant_id
               JOIN product p ON p.product_id = pc.product_id AND p.status = 'active'
               WHERE s.atc IS NOT NULL AND s.atc <> '' AND s.inn_en IS NOT NULL
               GROUP BY s.atc, s.inn_en"""):
        slot = exact.setdefault(atc, {})
        slot[inn] = max(slot.get(inn, 0), int(n or 0))
    agg: dict[str, dict[str, int]] = {}
    for atc, inns in exact.items():
        for ln in ATC_ING_LEVELS:
            if len(atc) >= ln:
                slot2 = agg.setdefault(atc[:ln], {})
                for inn, n in inns.items():
                    slot2[inn] = max(slot2.get(inn, 0), n)
    return {code: [[k, v] for k, v in sorted(d.items(), key=lambda kv: -kv[1])[:ATC_ING_TOP]]
            for code, d in sorted(agg.items())}


def build_cat_word_index(db: sqlite3.Connection, entries: list[dict]) -> dict[str, int]:
    """把「类别词 → 大类」+ 每类 top200 切片 + ATC 成分表预生成到 data/idx/。

    对应 reports/search-discovery-audit-20261110.md §2.3；实测体积见
    reports/v0103-search-impl-20261110.md §7（0.96 MB raw / 0.14 MB gzip，+18 个文件）。
    """
    idx_dir = OUT / "data" / "idx"
    words: dict[str, str] = {}
    cats: list[dict] = []
    for cat in CONSUMER_CATEGORIES:
        for label in (cat.get("labels") or {}).values():
            if label:
                words[_cat_norm(label)] = "cat:" + cat["id"]
        words[_cat_norm(cat["id"])] = "cat:" + cat["id"]
        prefixes = list(cat["prefixes"])
        totals = dict(_ing_totals(db, prefixes))
        hit = [e for e in entries
               if e.get("atc") and any(str(c).startswith(p)
                                       for c in e["atc"] for p in prefixes)]
        hit.sort(key=lambda e: (-max((totals.get(s, 0)
                                      for s in str(e.get("x") or "").split(" + ")),
                                    default=0), -(e.get("n") or 0)))
        top = [{f: e.get(f) for f in CAT_SLICE_FIELDS} for e in hit[:CAT_SLICE_TOP]]
        name = f"cat-{cat['id']}.json"
        (idx_dir / name).write_bytes(json.dumps(
            top, ensure_ascii=False, separators=(",", ":")).encode("utf-8"))
        cats.append({"id": cat["id"], "url": f'cat/{cat["id"]}.html',
                     "prefixes": prefixes, "labels": dict(cat.get("labels") or {}),
                     "atc4": _atc4_of(db, prefixes),
                     "ing": [[inn, n] for inn, n in _ing_totals(db, prefixes)[:16]],
                     "slice": {"f": "data/idx/" + name, "n": len(top)}})
    # 口语词：与 categories.json 的 aliases 同一份表（已剔除防遮蔽白名单）
    for cat_id, words_list in colloquial_aliases_by_category().items():
        for w in words_list:
            words[_cat_norm(w)] = "cat:" + cat_id
    groups = _atc_groups(db)                      # 已算好的 L1/3/4/5 分组，不另写一遍

        {"v": BUILD_V, "codes": codes_ing},

    return {"words": len(words), "cats": len(cats), "atc_ing": len(codes_ing),
            "bytes": (idx_dir / "cats.json").stat().st_size}
```

   命中 `words[_catNorm(nq)]` → `cat:` 走 `renderCategoryFast()`、`atc:` 走 `renderATCFast()`；
   未命中/失败 → 返回 false，继续今天的逻辑。ATC 码用 `atcQuery()` + `atc-ing.json` 的 key 判定，
   不依赖 `words`。
3. **`renderCategoryFast()` / `renderATCFast()`**：输出与现 `renderCategory()` /
   `renderATC()` 同构（解析条 + 类目页链接 + `cat.disclaimer` + 分组表），数据源换成切片 /
   成分摘要；成功后 `loadIndex(true)` 在后台补全（沿用 `build.py:5105` 的「core 到位重绘」机制）。
   切片缺 `m/mu/ml`（厂家列，见 §7.2）→ 首屏该列显示 `—`，core 到位重绘后补齐；这是刻意的取舍
   （带上厂家列要 +1.37 MB raw / +0.30 MB gz）。
4. **排序口径同步**（`renderCategory` / `renderATC` 里 `hits.sort(...)` 之前）：用
   `CATX.cats[].ing`（大类）与 `atc-ing.json`（ATC 码）建 `ingWeight` 映射，把排序键换成

## 10. 风险与缺口

1. **`build.py` 是另一个会话的活动文件**（本会话期间 10,684 → 11,391 行，`#1`+`#2` 的构建期
   与客户端实现都已由它写入）。本会话**一行都没改** `site/build.py`，§8 只做核对；
   §8.0 的 F1–F5 需要它的 owner 决定改不改。
2. **构建期断言已接线**：`main()` 现 11,363 行调用 `assert_no_unlisted_shadow(db)` ——
   新的「口语词 = 真商品名」撞车会让建站直接失败（比线上遮蔽好），但也意味着
   **以后扩充口语词表时必须同步维护白名单**，否则构建红。
3. **客户端排序与 lib 的口径仍有 2 处不严格相等**（§8.0 F4a / F4b）：ATC 码线上仍按单卡条数；
   大类权重表只有 top16。24 条用例实测 rank 0 差异，所以不影响本批验收，但「同一查询在
   lib 与浏览器里顺序一致」还不成立。
4. **口语词接管「名字包含」命中**（§4.3）：`他汀` 29 条、`胃药` 3 条、`感冒药` 3 条、
   `消炎药` 2 条 从「几条名字匹配」变「整类候选集」。这是产品意图，但必须在发布说明里写，
   并保留「真实商品名不被整类化」的验收（`消炎药膏` 用例已在单测里）。
5. **`antibiotic` 的处理是例外表，不是规则自动推导**：例外表只存「哪个词让给药名/俗称检索」，
   不涉及商品名/成分/碰撞判定，符合 AGENTS §1.2（碰撞仍然自动推导）。新增撞车会被
   `assert_no_unlisted_shadow()` 拦下，但**拦下的处理仍需人/agent 判断**（删词还是加例外）。
   另外审计说「`antibiotic` 会遮蔽商品名」不准确：今天它已被 `aliases.json` 的俗称层接住
   （`v:null` 的类别叫法），并不返回那 7 个软膏商品名（§4.3）。
6. **`atc-ing.json` 超预算 3.4×**（§8.0 F1）：ATC 码首查 234 KB raw / 75 KB gz，
   仍是 43 MB 的 1/400，但比审计的 62 KB 计划大 3.4 倍；名称表占 58%。
7. **切片缺 `l`（碰撞级别）与 `m/mu/mn/ml`（厂家列）**：首屏缺「不可互换」角标与厂家列，
   core 到位重绘才补齐。`l` 建议补（+37.6 KB raw / +1.3 KB gz），厂家列不建议（+1.37 MB）。
8. **7 位 L5 成分码（如 `C07AB02`）与 5 位 L4 类码仍走 core 路径**：这类码首查还是慢（今天的行为）；
   审计也建议不做逐码切片（+31 MB raw）。属已知缺口。
9. **三语脚本在 Windows 控制台直接跑会 `UnicodeEncodeError`**（打印 `✓` 时 gbk 编码失败），
   需 `PYTHONIOENCODING=utf-8`（`ci_checks.py` 里已经这么设了）。既有问题，与本批无关。
