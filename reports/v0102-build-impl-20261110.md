## 2. 类别发现快车道（实测产物，SITE_OUT 到 `.tmp/v0102-idx`）

| 产物 | raw | gzip | 报告原型 |
|---|---:|---:|---|
| `data/idx/cats.json` | **23,180 B**（125 words / 16 cats / 1,154 atc_codes） | 7,200 B | 22,881 / 7,022 |
| `data/idx/cat-<id>.json` ×16 | 654 KB 合计（35–69 KB/个） | ≈100 KB | 654 KB / 109 KB |
| `data/idx/atc-ing.json` | **214,253 B**（355 codes / 2,581 names） | ≈73 KB | 62 KB / 25 KB |

- **`atc-ing` 超原型 3 倍的结构原因**：它带一张 `substance_id → [英名, 中文名]` 名字表（2,581 条，占 raw **58%**），
  换掉 355 个码里重复出现的名字；砍掉中文名会让 zh 用户看到英文成分名，故保留。
  **硬阈值（lead 定）：raw > 300 KB 就拆成「码表 + 名字表」两个文件按需加载。** 当前 212 KB 在范围内。
- 首查路径：`startFastLane()`（类别词 → 切片；ATC 码 → 成分表）→ 失败/判定不了回退 `startSlowLane()`
  （v0.10.1 行为逐字节不变）。切片 404 / JSON 坏 / 老缓存 → 老路径，不弹错。
- 不静默截断：ATC 成分表带 `t`（每码成分总数），只显示前 15 个时页面写「另有 N 个成分，完整索引加载完成后显示」
  （`atc.ing_more`），core 到位后 `renderATC()` **整块替换**这一屏，不会留下半截列表。
- 排序：大类用 `cats[].ing`、ATC 码用 `atc-ing` 的 `[sid, 产品数]`，与 `lib/search.py` 方案 H 同口径。
- 防遮蔽：`assert_no_unlisted_shadow(db)` 进构建入口；`antibiotic`（真实商品名）在 `NAME_KEY_SHADOW_EXCEPTIONS`。

## 3. 首屏与移动端（收口 perf 批）

- **发现并修掉一处「假门控」**：`ensureCoreInBackground()` 原来只靠 `requestIdleCallback`，空闲页面里几乎立刻触发
  → 等于「输入 2 字就拉 9.9 MB」。现在先等 **9 s 安静期**（`CORE_BG_DELAY=9000`）再排空闲回调。
- **`acUpdate()` 不再抢跑 core**：原来只要打字 ≥2 字就 `loadIndex()`；现在「快车道/分片在路上」时不拉
  （`LANE_BUSY`），分片到位后用它算补全提示。真 Chrome 实测：`at` → 300 ms / 3 s 内 `core.json` **0 次**，
  9,028 ms 才 1 次。
- **core 失败不再覆盖已有结果**：分片/切片已出结果时只 console 警告（`FAST_SHOWN`）。
- i18n 按语言拆包：`assets/i18n.<lang>.js` ×4 + 四语全量 `i18n.js` 保留（404 / 老缓存 / 回落）；
  `boot.js` 先判语言再插包，`onerror` 回落全量；`LANG_PICK_JS` 是 boot 与 i18n 共用的唯一一份语言判定。
- sticky 纳入 `#meta` / `#country`（`.searchbar` 作为 `#ac` 的新锚点）；CSS 三修：复选框 44 px、
  `.m-en/.m-zh` 14 px、横滑提示只桌面（`min-width:768px`）。
