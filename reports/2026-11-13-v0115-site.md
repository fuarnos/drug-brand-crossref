### 2.2 与报告不一致 / 需更正的地方

1. **报告 §1「load_index() 回填」措辞易误读**：回填在 **Python 构建期 `load_index()`**（L8637），不是前端 JS 的

2. **报告 §2「改样式 → 125,751 个文件」偏高约 8.6k**：实测 dist 中 **8,647 个 combo stub 页**
   （`_combo_stub_html`，内联 mini `<style>`、无共享 CSS / boot.js / BUILD_V，共 25.4 MB）在样式变化时

   不是 bug，但发布核对时不要拿这两个数字直接对账。

### 2.3 报告未覆盖的风险

1. **跨页缓存碎片化（新引入，中风险）**：`<link rel=stylesheet href="assets/style.<hash>.css?v=<页面hash>">`
   —— CSS 文件名已含内容哈希，再叠加**每页不同**的 `?v=`，浏览器 HTTP 缓存按完整 URL 命中 →
   **每进一个新页面都会重新下载 67 KB CSS**（v0.11.4 是全站同一个 `style.css?v=BUILD_V`，缓存一次）。
   `boot.js?v=<页面hash>` 同理（18 KB）。建议：CSS 去掉 `?v=`，boot.js 改用 `BUILD_V` 或哈希文件名（各一行）。
   **本报告未改**，等 Lead 拍板（改完需再全量构建一次）。
2. **`BUILD_V` 仍哈希 build.py 全文**（`_compute_build_v`，L102）：本次只改一句法语说明也会让
   `BUILD_V` 从 `2552531855` → `0456842107`，于是 **9 个 JS 资产 + 3 个 data JSON**（`atc-ing.json`/`cats.json`/`manifest.json`）
   必然重传。发布预估要把这 12 个文件算进去（不影响 12 万 HTML）。
3. **CSS 哈希名在 import 时定值**：目前 CSS 常量之后不再变，安全；若以后在 `main()` 里改 CSS，
   哈希名会与内容不一致。建议加一行断言（`sha256(CSS)[:10] == CSS_FILE 后缀`）。
4. **数据更新仍只靠 CDN/TTL 刷缓存**（既有设计，非本次引入）：`BUILD_V` 刻意不含 DB，页面 HTML 也不含数据版本 →
   数据 JSON 的 `?v=` 不随数据变。R2 的缓存 TTL 需在发布后确认（本次不阻塞）。
