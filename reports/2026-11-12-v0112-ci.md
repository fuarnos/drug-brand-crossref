## 2. 非 PASS 项逐条说明

### 2.1 `unittest:lib-atc-category` —— 既有红，不是 v0.11.2 引入

**失败点**：`tests/test_lib_atc_category.py:55` 的 `test_snapshot_sync_with_dist`，把 `lib/categories.py` 的
`CATEGORY_SNAPSHOT` 和构建产物 `site/dist/data/categories.json` 逐字段比对，`antihypertensives` 不一致。

**为什么会红（根因）**：不是「多了一条别名」，而是**16 个大类全部不一致**，且方向单一 —— dist 有、lib 快照没有：

```
lib 快照 aliases 合计 32 条（每类 2 条，只有官方 label/alias）
dist       aliases 合计 97 条
差 65 条 = COLLOQUIAL_ALIASES 66 条 − NAME_KEY_SHADOW_EXCEPTIONS 1 条
```

即 `lib/categories.py` 的**口语别名表（66 条）在 v0.10.3 被接进构建**（`categories.json` 的 aliases 与
`data/idx/cats.json` 的 words 都从它生成），但 `CATEGORY_SNAPSHOT` 这份「镜像快照」**没有跟着重建**。
`lib/categories.py` 自己的 docstring 就写着「同步方向只有一个：build.py（线上真相）→ 本快照」——
**这次是快照落后了**，用例判红是正确的，该改的是快照（或把口语词从比对范围里摘出去）。

典型差异（dist 独有）：

| 大类 | lib | dist | dist 独有（节选） |
|---|---:|---:|---|
| antihypertensives | 2 | 8 | 降血压药 / 降血壓藥 / 降压药 / 降壓藥 / blood pressure medicine / blood pressure medicines |
| analgesics | 2 | 13 | 退烧药 / 退燒藥 / fever medicine / painkiller / 止痛药 … |
| statins | 2 | 6 | 他汀 / statin / 降脂药 / 降脂藥 |

**证明「与 v0.11.2 无关」的三条证据**：

1. `site/dist/data/categories.json` 在 v0.10.3 / v0.11.1 / v0.11.2 三份产物里 **sha256 完全相同**
   （`F80B55888C34019B…`，300,265 B）——构建侧这两个版本没动过这个文件。
   ```
   site\dist\data\categories.json                                    300265 F80B55888C34019B  11-11 10:36
   .tmp\publish-opt\gh-pages-cache.broken-20261111\data\categories.json 300265 F80B55888C34019B  11-10 13:53  ← v0.11.1
   .tmp\dist-v0103-final\data\categories.json                        300265 F80B55888C34019B  11-09 16:19  ← v0.10.3
   ```
2. `git status --porcelain lib/categories.py` 为空 —— lib 侧也未随 v0.11.2 改动。
3. 同一份输入 → 同一输出：这条用例在 v0.11.1 的产物上跑，结果必然一模一样。

**为什么一直没被发现**：这条用例只在 `ci_checks.py` **全量模式**跑（`--fast` 会记 SKIP，见 `deploy/ci_checks.py:264`，
理由写着「47 s，挪到全量」）。日常用 18 秒的 `--fast` 做基线，就永远看不到它。

**建议**（不属本任务，未改代码）：单独开一条 —— 把 `CATEGORY_SNAPSHOT` 重建到与 v0.11.2 产物一致（或改成构建期从
`COLLOQUIAL_ALIASES` 派生，消灭这份手工镜像），并考虑让 `--fast` 至少跑这条（0.005 s，无需 Chrome）。

### 2.2 `trilingual` —— 本机环境限制，串行重跑达标

CI 内的真实报错（不是测试失败，是连测试都起不来）：

```
File "...\multiprocessing\connection.py", line 575, in Pipe
    h2 = _winapi.CreateFile(
PermissionError: [WinError 5] 拒绝访问。
```

`ci_checks` 用 `jobs=8` 跑 `tests/trilingual/run_tests.py`，8 个 worker 走 `multiprocessing` 命名管道，
被本机 sandbox 拒绝（同 sandbox 策略下 Chrome/CDP 也起不来，见 §2.3）。

**串行重跑结果（`--jobs 1`，562.8 s）**：

```
== 汇总 ==
案例 72（通过 69）；查询 354 条：Top-5 命中 98.6%，Top-1 命中 95.5%；跨国可见 72/72；用时 562.8s
  en: 123 条查询, Top-5 121, Top-1 115 (98.4%)
  es: 116 条查询, Top-5 114, Top-1 112 (98.3%)
  zh: 115 条查询, Top-5 114, Top-1 111 (99.1%)
```

3 个失败案例与 `ci_checks.ALLOWED_TRILINGUAL_FAILURES` 对照：

| 案例 | 类别 | 在允许清单 | 表现 |
|---|---|---|---|
| metformin | combo | ✅ | 既有（combo 类 5 例过 4） |
| beclometasone | dup_inn | ✅ | 查询 1/3 命中 Top5（`beclomethasone` 16 cards、`beclometasona` 14 cards，Top1 均为 Beclomethasone） |
| chlorphenamine | dup_inn | ✅ | 查询 2/3 命中 Top5（`clorfenamina` 17 cards，Top1 = Chlorpheniramine + Tramazoline） |

按 `deploy/ci_checks.py:284-298` 的判定分支：`cases=72 ≥ 72`、`passed=69 ≥ 68`、`unknown=[]` → **应记 PASS**。
所以这一项**不构成发布阻塞**，只是本机跑不出 CI 的并行形态。
