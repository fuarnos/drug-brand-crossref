## 2. `core-json-size` 深挖：护栏口径问题，不是站点问题

`deploy/verify_live.py:265-274` 的逻辑：先请求 `data/idx/core.json`；若 `Content-Encoding` 为 gzip，
用 **`Content-Length`** 与该区间比较；否则用 raw 区间。R2 这次返回 **gzip + chunked、没有 Content-Length**，
于是 `clen = None` → 直接判 FAIL（提示文案就是「core.json 缺 Content-Length」）。

### 2.1 实测（`.tmp/core_probe.py`，只读）

| 项 | 值 |
|---|---|
| URL | `https://drugcrossref.com/data/idx/core.json` |
| HTTP | **200** |
| `content-type` | `application/json` |
| `content-encoding` | `gzip` |
| `content-length` | **null（缺失）** |
| `transfer-encoding` | **chunked** |
| `etag` | `W/"558be8983f62f25c307a2c5295923b38"` |
| `last-modified` | `Wed, 11 Nov 2026 18:52:14 GMT`（= 本机 10:52:14，本次上传后 1 分钟内） |
| `cf-cache-status` | `DYNAMIC` |
| wire bytes（gzip 传输） | **9,816,074 B** |
| 解压后 | **42,801,654 B** |
| 与本地 `site/dist/data/idx/core.json` 比对 | **逐字节相同（True）** |
| 本地文件大小 | 42,801,654 B |
| 解压后重新 `gzip -9` | **9,801,041 B** |
| `verify_live` 护栏区间 | gzip **2,500,000–12,000,000 B** / raw **11,000,000–50,000,000 B** |
| 若按 body 判定 | **落在区间内 → 应 PASS** |

### 2.2 结论

- 主域 `core.json` **可访问、内容正确、体积合规**；失败仅因 R2/Cloudflare 对 gzip JSON 采用
  `Transfer-Encoding: chunked`（不返 `Content-Length`），而检查脚本假设该头必然存在。
- 与 gh-pages 的差异：GitHub Pages 会带 `Content-Length`，所以同一检查在 gh-pages 侧一直是 PASS。
- 这也解释了为什么 v0.11.0 时没暴露：当时的记录显示本机对 `drugcrossref.com` 是 TLS 拦截误报
  （`reports/2026-11-11-r2-closeout.md` §「本机直连不可用」），R2 侧没真正跑过这套检查。

### 2.3 建议修法（**未执行**，`deploy/**` 不在本任务写权限）

```python
# deploy/verify_live.py 约 268 行，加一句兜底：
clen = resp.headers.get("Content-Length")
if clen is None:                      # R2/CF 对 gzip JSON 用 chunked，不带该头
    clen = len(gzip.compress(body, 9, mtime=0)) if cenc == "gzip" else len(body)
```

改完重跑同一条 verify 命令即可 0 failures（预期 31/31）。

## 3. 护栏兜底（task-24，2026-11-12 11:36 PDT / 03:36 北京）

- 改动文件：**`deploy/verify_live.py`**（授权范围仅此文件；未改其它检查、未改 dist、未重跑 build/publish/sync）。
- 思路：`core.json` 的 HEAD 若无 `Content-Length`（R2 走 gzip + `Transfer-Encoding: chunked`），**补一次 GET**，用实际读到的字节数判定：
  gzip 用压缩后的 wire 字节（`wire_bytes`），明文用解压后的 body 字节；**护栏 `CORE_GZ_RANGE` / `CORE_RAW_RANGE` 一字未改**。
- 关键 diff（两处）：
  ```diff
  -    clen = int(core["headers"].get("content-length") or 0)
  +    # R2 对 core.json 走 gzip + chunked，HEAD 没有 Content-Length；补 GET 用实测字节兜底
  +    if core["status"] == 200 and not int(core["headers"].get("content-length") or 0):
  +        core = get("data/idx/core.json")
  ...
  -    checks.add("core-json-size", False, "core.json 缺 Content-Length")

  +                                            int(core.get("wire_bytes") or 0))
  ```
