## 1. 根因（修正了调研报告的一条假设）

不是祖先 `overflow` 裁切（`.listfilters` 并不在 `.formchips` 里），而是它直接挂在 `.drug-sticky` 上：

- `.listfilters{position:relative}` → 浮层 `.lf-panel{position:absolute;left:0}` 锚在**最右侧那个「筛选」chip** 上；
- `.lf-panel` 只有 `min-width:min(92vw,640px)`、**没有 max-width** → 直接撑出视口。

用户截图那个 bug 的直接证据：**1440 视口下 `.lf-panel` 的 `right=1755px`、`document.scrollWidth=1755`** → 整页横向滚动、右侧 chips 看不见。

## 2. 改法（8 处，纯 CSS）

| 位置 | 改动 |
|---|---|
| token | 新增 `--float-gutter:12px` / `--float-max-h:min(70vh,560px)`，后续浮层优先复用 |
| `.lf-panel` | 包含块交给 `.drug-sticky`（已是定位祖先、宽度 = 内容带）；`width:min(92vw,640px)` + `min-width:0` + `max-width:calc(100vw − 24px)` + `max-height:var(--float-max-h)` + `overflow:auto` |
| `.lf-panel` @≤767 | `position:fixed` 贴底抽屉（`bottom:64px + safe-area`，让开 56px tabbar） |
| `.lf-panel` @高≤640 | 贴底固定浮层（横屏手机 / 小窗），`max-height:calc(100vh − 24px)` |
| `.catfinder` / `.cf-chips` | 同上：包含块上移 + 同样钳制 + 手机/矮视口贴底 |
| `.sn-panel` | 补 `max-width:calc(100vw − 24px)` + `max-height:calc(100vh − 96px)` + `overflow:auto` |
| `#ac`（搜索建议） | `overflow:hidden` → `overflow:auto` + `max-height:min(50vh,420px)` + `overscroll-behavior:contain` |

## 5. 缺口

1. **Esc 关闭浮层 / 内容真涨到 `max-height` 时的 JS 翻转**：按 R3 调研结论（零依赖纯 CSS 优先）留后续；当前靠「钳制 + 内部滚动 + 手机抽屉」保证不裁切。
2. **首屏守卫读数不稳**（并行 Chrome / 同 CSS 重跑差异）→ 队列 Q11，目标 v0.13.5。
3. `@media (max-width:767px){main .drug-sticky{display:none}}` 让「成分页手机底部抽屉」当前不可达（保留样式，等粘性条回到手机端直接生效）。
