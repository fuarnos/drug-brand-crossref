### 为什么是 72k 而不是预想的 ≈31k

本版**不只是新增 29,824 个静态 product 页**：`PRODUCT_STATIC_TOP_N` 54,176→84,000 后，站内所有指向这些产品的链接
从 `../product.html?pid=<pid>`（20 B）改成 `../product/<pid>.html`（16 B），**每处链接 -4 B**，于是 **40,016 个既有页面被字节级重写**
（product 35,375 / drug 2,331 / name 2,285 / assets 8 / 根 3 / 六语 12）。差值全为 -4 的整数倍（-4 19,554 页、-8 13,659 页、-12 4,354 页 …）与链接数量成正比。

用线上 v1.2.1 与本机新 dist 逐字节对照确认（例）：

```
name/alltec-f-c.html      live 6780 B / local 6776 B
  LIVE : <a class="p-rec" href="../product.html?pid=TW-TFDA-043213-cb950e62" ...
  LOCAL: <a class="p-rec" href="../product/TW-TFDA-043213-cb950e62.html" ...
product/US-0006-3026.html live 8638 B / local 8630 B（同一位置，两处链接）
```

结论：**这是静态页扩容的必然副作用（链接结构改进，非模板回归）**；要压到 ≤31k 只能改链接策略，属源码决策，不在 release 权限内。
`69,841 = 29,825 added + 40,016 size-changed`，与 planned 72,114 的差额 ≈2,274 为「大小相同但校验和不同」的页面（长度被抵消的改写）。

## 6. A/B 差分（步骤 6）

`site/dist` 现清单（`.tmp/v122-dist-after.txt`，302,107 行）vs `.tmp/v122-dist-before.txt`（272,283 行，v1.2.1 产物）：

| 指标 | 路径级差分 | 说明 |
|---|---:|---|
| added | **107,767**（真实 **29,825**） | 真实新增 = `product/` 29,824 + `assets/` 1；`name/` 77,942 全是伪影 |
| removed | **77,332**（真实 **1**） | 真实删除 = `assets/` 1（旧哈希资源，已被 keep-alive `--exclude` 保活）；`name/` 77,331 全是伪影 |
| size-changed | **40,016** | 全部是 §5 的链接改写：product 35,375 / drug 2,331 / name 2,285 / assets 8 / 根 3 / 语种 12 |

**`name/` 的 77,942 / 77,331 是 before 清单的编码伪影，不是真实改名**：

- `.tmp/v122-dist-before.txt` 的非 ASCII 文件名被按 ANSI(GBK) 落盘，读回即乱码。`name/人生-胃治康-齊锭.html`（真实文件）
  在 before 里是 `name/浜虹敓-鑳冩不搴?榻婇敪.html`；该乱码行**确实存在于 before 清单**，说明是同一文件的两种编码。
- 数量吻合到个位：新 dist 中 `name/` 的非 ASCII 路径数 = **77,942** = added 的 `name/` 数；before 里 ASCII 的 `name/` 路径全部匹配（0 新增 / 0 删除）。
- 乱码里不可映射字符被写成 `?`，导致 272,283 行折叠成 271,672 个唯一路径（611 行重复），也解释了这一点。

真实口径（供验收）：**added 集中 `product/`（29,824）+ assets 1；页面 removed = 0**，符合「内容增长非回归」。
长尾六类（`name`/`drug`/`combo`/`maker`/`atc`/`cat`）文件名 0 新增 0 删除，只有既存页面的链接目标改写。
