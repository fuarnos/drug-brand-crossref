# v0.10.2 i18n 四语门禁审计（2026-11-10）

> 用户规则（2026-11-10）：**多语言翻译要同步更新，写进底层逻辑，不能英语和西语滞后。**
> 本报告是这条规则的第一版审计 + 门禁落地记录。所有数字为**现查**，命令逐条写在 §11，可复跑。
> 本轮**没有**改 `site/build.py`、没有建站、没有发布、没有提交 git。

## 1. 结论

1. **UI 字典层（531→493 键）四语其实是齐的**：en / es / zh / zh-Hant 合并后各 **493 键，缺 0 条、陈旧 0 条**，
   `data-i18n` 引用 188 处、服务端直取 16 处，**没有一处指向不存在的 key**。所以「西语滞后」不是字典缺键造成的。
2. **真正滞后的是三处**：
   - **release notes（What's new）**：最新版 `v0.10.1` 在 `data/release_notes_i18n.json` 里**根本没有译文**；
     `v0.8.3 → v0.10.1` 共 **13 版 60 条**没有译文，`v0.8.2` 只译了 9 条里的 5 条 —— en/es 用户现在看到的是
     **中文原文 + 「译文待补」**（`site/build.py:6412-6425` 的兜底逻辑）。这是「英语和西语滞后」最集中的地方。
   - **术语不一致（es）3 条**：`LABEL_I18N` 的 `form.inhalation`（`inhalado`）、`form.pellet`（`pellet`）、
     `form.stick`（`stick`）与仓库自己的术语表 `data/label_translations.csv`（`inhalación` / `pélete` / `barra`）不符。
   - **硬编码文案 9 处**：HTML 模板里直接写死、没走 `data-i18n`（如 404 的 `<title>`、About 的「Data package」四个链接、
     组合页 stub 的中英混排），这 9 处中英/英西永远同串，语言切换无效。
3. **门禁已经落地并接进 CI**：`deploy/i18n_check.py`（新文件，只读、纯静态、**0.6 s**）+ `deploy/ci_checks.py` 的
   `check_i18n()`（**fast 模式也跑**，失败即红）。自检 17 项全绿，变异测试（删一个 es key / 只加中文 key）能精确报出 key 名。
   当前 `python deploy/ci_checks.py --fast` 因为上述 release notes 缺口**是红的**（这是设计意图，不是故障）。
4. **`site/build.py` 的底层拦截已写好补丁**：`.tmp/i18n-gate/patch.diff`（89 行，4 处改动，`git apply --check` 通过），
   在 `main()` 写任何页面之前 `_assert_i18n_complete()` 硬拦四语不一致。**等放行后落地**（见 §9）。

## 3. 审计方法与口径

- 解析方式：用 `ast` 解析 `site/build.py`（**不 import**，避免构建副作用），取出 18 个 `*_I18N` 字典常量，
  按 `build.py` 的真实装载顺序复刻合并：`I18N` 打底 → 模块级 `COVERAGE_I18N` / `NAME_LANG_I18N` →
  `_merge_static_i18n()` 的 13 个字典；`ATC_L1_I18N` / `ATC_CLASS_I18N` 只服务端用、**不进** `I18N`。
- 「合并后字典」= `i18n.js` 实际下发的字典，共 **493 键**（与构建日志里的数字一致；
  另 38 键属于 ATC 大类/一级类名，单独按四语键集检查）。
- zh-Hant 的判据来自 `build.py` 的 `_install_zh_hant()`：**简体 zh 兜底 → `data/i18n_zh_hant.json` → build.py 的 zh-Hant 块**，
  所以「繁体缺键」= json 和 build.py 都没给，运行时会静默显示简体。

## 6. `data/i18n_zh_hant.json`（简体兜底 + 覆盖）

| 指标 | 数值 | 判定 |
|---|---:|---|
| json 里的 zh-Hant 键 | 346 | — |
| build.py 里 zh-Hant 块的键（只算进 `I18N` 的 9 个字典） | 240 | — |
| 两者都写（重复定义） | 93 | 正常 |
| 只有 build.py 写（新 key 不依赖 json） | 147 | 正常 |
| 只有 json 写 | 253 | 正常 |
| 合并后 zh-Hant 总键 | **493** | = 简中键数，**0 缺** |
| 陈旧 key（json 有、base 没有） | **0** | 无 |
| 与简中同值且含简体专用字（=没转换） | **0** | 无 |

> 判别方法：先用「只在简中文本出现、繁中文本从不出现」的字集（`zh 值字符集 − zh-Hant 值字符集`）筛，
> 再要求该 key 的 json 值与 zh 值完全相同。这样 `模糊 / 拼音 / 同成分的商品` 这类**繁简同形**的文本不会被误报
> （早期粗暴版本曾误报 4 条，已修正）。
>
> 顺带发现：`build.py` 的日志 `i18n zh-Hant: … (346 from json, 147 fallback zh)` 把 147 条
> 「json 没覆盖、但 build.py 的 zh-Hant 块给了繁体值」也统计成 fallback，数字会让人误以为有 147 条回落简体。
> 补丁里的 `ZH_HANT_FALLBACK_KEYS` 用的是**扣掉 build.py 显式值**的口径（真回落 = 0），建议同时把这行日志改准（见 §9 待办 4）。

### 9.1 命令


### 9.2 规则分级

| 级别 | 规则 | 触发条件 |
|---|---|---|
| **FAIL** | `dict-key-missing` / `eff-key-missing` | 某语言缺 key（打印完整清单） |
| **FAIL** | `pseudo-translation` | 非 en 值与 en 完全相同且不在白名单（专有名词/单位/有意同形） |
| **FAIL** | `zh-hant-untranslated` | json 繁体值与简中同值且含简体专用字 |
| **FAIL** | `release-latest-missing` / `release-latest-incomplete` | 最新版 release notes 缺语言或条数不符 |
| **FAIL** | `label-term-mismatch` | 剂型/释放机制译名与 `data/label_translations.csv` 不符 |
| **FAIL** | `template-ref-missing` / `template-direct-missing` | `data-i18n` 或 `I18N["xx"][…]` 指向不存在的 key |
| WARN | `pseudo-suspect` | 同形但命中「可疑白名单」（缩写 / 外来词） |
| WARN | `dict-key-extra` / `zh-hant-stale` / `release-stale` / `release-meta` | 陈旧 key / 元数据不符 |
| WARN | `release-backlog` / `release-backlog-incomplete` | 历史版本缺译文（聚合一条，逐版明细在 JSON） |
| WARN | `hardcoded` | 模板里的裸文案（标注影响哪些语言） |
| INFO | `label-term-ok` / `hardcoded-info` / 同形放行 | 已登记的有意差异 |

### 9.4 门禁本身怎么证明有效

- `--self-test`：17 项断言全绿，覆盖「缺 key / 同值英文 / zh-Hant 未转换 / 术语不符 / 模板引用不存在 / release 条数不符 / 只抓无 `data-i18n` 的裸文案」。
- **变异测试**：把 `site/build.py` 复制一份，删掉 `LABEL_I18N.es["form.gas"]`、给 zh 加一个仅中文的 `form.newsample`，
  门禁精确报出：

```
[dict-key-missing] LABEL_I18N 的 es 缺 1 个 key → form.gas
[eff-key-missing]  合并后 es 缺 1 个 key（运行时会静默回落 英文）→ form.gas
[eff-key-missing]  合并后 zh-Hant 缺 1 个 key（运行时会静默回落 简体 zh）→ form.newsample
[dict-key-extra]   LABEL_I18N 的 zh 多出 1 个字典里不存在的 key（陈旧 / 拼错）→ form.newsample
```
