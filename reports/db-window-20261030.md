## 4. hash 记录口径（窗口报告必须）

- **products/components/substances/variants/name_keys/names**：COUNT。
- **unit hash**：`normalize_strength.py` 按 `product_component` 的 `(strength_unit,per_volume_unit)` 内容计算（副本验证用 sha256；窗口执行时跑 dry-run/或 `verify.py` 同口径记录 before/after）。
- **component hash**：`fix_pseudo_combos.py` 对 `product_component` 全行 repr 的 sha256（副本验证：apply 前 `6d6562e3604911b2`、apply 后不同、rollback 后回到原值）。
- **coverage**：`select * from coverage order by country`。
- **DB size**：bytes。
- **备份 sha256**：见 §0。

## 9. 跨产品 salt substance 合并（另开审计，不并入本窗口）

- 现象：同一 base 的不同 **substance 记录**（如 `Atorvastatin` 与 `Atorvastatin Calcium`）被不同产品/来源使用，导致 key 级伪复方 **545 key / 8,798 产品**（`data/pseudo_combo_issues.csv`；collision severe 477）。
- 本窗口**只做** task-137 的 214 产品/285 行同产品重复修复；**不做**跨产品 substance 合并。
- 另开审计/任务方案（优先级低于 build 层归并）：
  1. **build 层按 base 归并**（零数据风险，建议先做）：索引 `vs/x/cu`、combo、collision 使用 base 去重；545 假 combo/假 severe 消失。
  2. 数据层 substance 合并：对每个 salt substance 找到 base（严格 salt 词表），把 variant 重挂到 base（必要时新建等价 variant），确认无引用后删除 salt substance；需 dry-run/清单/副本验证，参照 `etl/auto_merge_substances.py`。
  3. 合并前审计口径：`data/pseudo_combo_issues.csv` key/base 映射 + `variant.salt_code` 对齐；不按首词盲并（避免 Sodium Chloride/Lactate、胰岛素类误并）。
- 该任务独立排期，不与 task-133 同窗口，避免身份变更与数据清洗互相污染。
