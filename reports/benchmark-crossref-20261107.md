# 对标案例：跨国药名对照 / 药品信息站（2026-11-07）

> 目的：给 UI 大修与产品定位找参照。**只看做法，不抄内容**；凡涉及「用药建议 / 剂量 / 替代推荐」的一律不采纳（我们的红线）。
> 方法：公开网页检索 + 读取公开帮助页（Vidal 帮助页原文最长，是本文主要依据）。图中无截图，避免版权问题，只记结构与做法。

## 0. 结论（对我们要紧的 5 条）

1. **「按 ATC 同类 + 剂型/给药途径筛选」的跨国对照，是有商业先例的**——Vidal 的「Équivalences internationales」就是：49 国、50 万药品、按 ATC 同类列出，并明确写「不是严格治疗学等价」，可再按给药途径、剂型收窄。这几乎就是我们 v0.9.5 做的 ATC4「同类 × 剂型 × 市场」事实表 + 免责措辞的翻版。
2. **身份对应要以「成分 + 规格 + 剂型」为轴**，不是品牌名——RxNorm/RxNav 的 crosswalk 是行业标准做法；我们已有的 `product × component × variant × strength` 结构是对的。
3. **用户真正的入口是「一个名字 → 各国都有哪些叫法」**：Index Nominum（40+ 国商品名索引）、World Drugs Converter（输入一国药名看另一国）都是这个模型。我们的「身份卡 + 国家矩阵」方向正确，但**缺少"按国家"的显式入口**（现在只有首页下拉和覆盖页）。
4. **大站都把「公众 / 专业」两种视图分开**（drugs.com、Vidal），专业视图才有相互作用、剂量等。我们只做公众视图的一半——事实层。若将来分视图，也只加「数据来源/方法」深度，不加用药建议。
5. **结果页密度可调**是成熟做法（drugs.com 表格/卡片；Vidal 结果按类别分块 + 字母索引）。我们 P1-14「大表无排序/密度控制」可以照抄这个思路，但**不排序推荐**，只做行高/列显隐。

## 3. 差异化（我们比它们多做的）

- **四语（en/es/zh/zh-Hant）同一站**：Vidal 只法语、Index Nominum 英语为主、Vademecum 西语——我们一屏四语。
- **同名不同药（collision）显式可见**：它们大多只做「成分 → 商品名」，我们额外标注「同一个名字在不同国家可能是不同成分」。
- **可下载的派生数据包 + 溯源字段**：少数（RxNorm 有 API），我们给 CSV/JSON + 来源/方法/置信度。

## 4. 不抄清单（红线）

- ❌ 任何「替代药」「可以换着吃」的推荐（Vidal 有 therapeutic alternatives，我们不做）
- ❌ 剂量计算/换算、给药方案
- ❌ 相互作用检查（需要完整相互作用数据与临床责任）
- ❌ 「按疗效排序」或评分（会把事实表变成推荐表）

## 5. 下一步建议（给 Lead 排期用）

1. **P0 已做**：身份卡 / 分页 / 零结果 / 粘性搜索 / 导航壳（v0.9.8）。
2. **P1**：ATC 页 4 个 notice 合并、H1 四语、覆盖页字段、404 补壳、字号/圆角统一（v0.9.9）。
3. **对标新增候选**（P2）：
   - 「按市场」落地页 `/market/<CC>.html`（借 Index Nominum 的国家轴）——体积 10 页，可接受；
   - 结果页「密度切换」（借 drugs.com）——纯 CSS；
   - 成分页加「该成分在本站覆盖 N 国 / M 条记录」（借 Vidal 首屏信息密度）。
