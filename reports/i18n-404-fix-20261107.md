# 「切换语言跳 404」修复（task-10）

> 2026-11-07 · 只改 `site/build.py`（+13 / −4）· 未提交、未发布、未写 `site/dist`
> 构建产物：`.tmp/build-i18n`（`SITE_OUT` 临时目录）

## 0. 结论

- **症状**：线上 v0.9.6 在**首页**（含搜索后的结果页 `index.html?q=…`）点语言 EN/ES/中文/繁 → 跳到**域名根**的 `/zh/index.html` 之类，GitHub Pages 返回默认 404「There isn't a GitHub Pages site here.」——正是用户截图。
- **根因一句话**：首页内联的 `new URL('' || "../", location.href)` 里 **`''` 在 JS 中是 falsy**，取到 `"../"`，在项目子路径 `/drug-brand-crossref/` 下解析成**域名根**（越过一层）；`langTarget()` 再拼 `ROOT + 'zh/index.html'` 就落到域名根。
- **修复**：`_optimize_home_html()` 里改用 Python 侧算好的前缀（`prefix or "./"`）；根级首页 → `./`（= 项目根），语言副本 → `../`（行为不变）。顺带把 `langTarget()` 副本页清单补上 `glossary.html`/`coverage.html`（它们本来就有 `/es/ /zh/ /zh-hant/` 副本，之前只能落 `?lang=` 变体）。
- **验证**：本地按 GitHub Pages **子路径**静态服务 + 无头 Chrome **真实点击**，**168 个「页面 × 语言 × 视口」组合：修复前 16 个 404（只有首页/结果页），修复后 0 个**；四语 `<html lang>` 与 H1 文案正确、`?q=` 保留、子页仍走 `?lang=`；`py_compile` 等 5 项 PASS（见 §5 的 `unittest:lib` 说明）。
- **影响面**：全站只有 4 个首页文件内联 `__DSH_I18N_ROOT`（`index.html` 与 `/es/ /zh/ /zh-hant/index.html`），其余 121,276 页都从 `assets/i18n.js` 的 `src` 推导 ROOT，**不受此 bug 影响**。

Lead 用静态推算扫过 76 组没复现，因此这里改成**真实浏览器点击**，且关键是**必须按项目子路径服务**（`serve.py` 在域名根服务，见 §3 的「为什么本地/CI 抓不到」）。

## 3. 根因（证据链）

1. **线上实测**（`.tmp/live-check.py`，只看状态码）：
   ```
   404  https://fuarnos.github.io/zh/index.html
   404  https://fuarnos.github.io/zh/
   200  https://fuarnos.github.io/drug-brand-crossref/zh/index.html
   200  https://fuarnos.github.io/drug-brand-crossref/zh/?q=tylenol
   200  https://fuarnos.github.io/drug-brand-crossref/zh/index.html?q=tylenol
   ```
   → 目标 URL 本身没问题（`/zh/index.html` 加 `?q=` 也是 200），**是跳错了前缀**。
2. **产物里的内联值**（`site/build.py` 的 `_optimize_home_html()`，旧代码）：
   ```html
   <script>window.__DSH_I18N_ROOT=new URL('' || "../", location.href).href;</script>
   ```
   首页的 `prefix = ""`，`f'...{prefix!r} || "../"...'` 生成 **`'' || "../"`**；JS 里 `''` 是 falsy → 取 `"../"`。
3. **URL 解析**（`.tmp/check-root.js`，node 复算）：
   ```
   index.html       表达式='' || "../"     ->  https://fuarnos.github.io/                      ✗
   es/index.html    表达式='../' || "../"  ->  https://fuarnos.github.io/drug-brand-crossref/  OK
   ```
   即：根级首页的 ROOT 越过项目根一层；语言副本（`prefix='../'`）**反而正确**（`../` 从 `/es/index.html` 正好回到项目根）——所以 bug 只出现在根级首页。
4. **拼接**：`langTarget()` 用 `ROOT + (LANG_PATH[code] || '') + m[1]` → `https://fuarnos.github.io/` + `zh/` + `index.html` = 域名根 → GitHub 默认 404。

**为什么只有首页**：`grep __DSH_I18N_ROOT` 全站产物 → 只有 `index.html`、`es/index.html`、`zh/index.html`、`zh-hant/index.html` 4 个文件有内联值（首页为了 LCP 把 i18n.js 内联，才需要显式告诉 ROOT）。其余页面走 `assets/boot.js` 动态加载 `assets/i18n.js`，`document.currentScript.src` 推导 ROOT，天然带项目前缀。这也解释了 Lead 静态扫「所有根级页面都会中招」的推测偏大：实测 about/coverage/… 都 200。

**为什么本地预览和 CI 抓不到**（node 复算）：
```
本地根服务  ./ -> http://127.0.0.1:8000/   ../ -> http://127.0.0.1:8000/   等价: true
Pages 子路径 ./ -> https://fuarnos.github.io/drug-brand-crossref/
Pages 子路径 ../ -> https://fuarnos.github.io/                                (bug)
```
`serve.py` 把 dist 服务在**域名根**，`..` 与 `.` 解析结果相同 → 本地永远复现不出；只有 GitHub Pages 的项目子路径才暴露。

## 4. 修复（`site/build.py`，+13 / −4）

```diff
 def _optimize_home_html(html: str, prefix: str) -> str:
+    # 根级首页 prefix='' 时，JS 里 '' 是 falsy 会取 "../" → ROOT 越过项目根；改用 Python 侧前缀
+    root_prefix = prefix or "./"
     boot = (
-        f'<script>window.__DSH_I18N_ROOT=new URL({prefix!r} || "../", location.href).href;</script>'
-        + f'<script>var _r=new URL({prefix!r} || "../", location.href).href;'
+        f'<script>window.__DSH_I18N_ROOT=new URL({root_prefix!r}, location.href).href;</script>'
+        + f'<script>var _r=new URL({root_prefix!r}, location.href).href;'
```
- 根级首页 → `new URL('./', ...)` = `https://fuarnos.github.io/drug-brand-crossref/` ✅
- `/es/ /zh/ /zh-hant/index.html` → `new URL('../', ...)`（与原来一致）✅
- 第二个 `_r` 是 `_coverage_entry_js("_r")` 注入「Coverage」链接用的同一个 ROOT，同一处 bug 一并修掉（首页已有静态链接，实际不会触发注入，但表达式不再留雷）。

顺手（同一函数族、同一类「URL 与语言不一致」问题，不产生 404）：
```diff
-    var m = relPath().match(/(?:^|\/)(index\.html|about\.html|confused\.html|whats-new\.html|warn\.html)$/);
+    var m = relPath().match(/(?:^|\/)(index\.html|about\.html|confused\.html|whats-new\.html|warn\.html|glossary\.html|coverage\.html)$/);
```
`glossary.html`/`coverage.html` 本来就有 `/es/ /zh/ /zh-hant/` 副本（每语 7 个文件），原来切语言只能落 `?lang=` 变体（能显示、但 URL 停在旧语言目录）；现在直接进对应语言副本（实测 200，见 §2）。

## 6. 风险与后续

1. **必须发版**：v0.9.6 线上产物仍带此 bug；修的是生成物（4 个首页 HTML + `i18n.js`），只有重新构建发布才生效。GitHub Pages 对 HTML 缓存约 10 分钟（`max-age=600`），发布后短时间内仍可能拿到旧 HTML，属正常。
2. **不改 dist**：本次只改 `site/build.py`，`site/dist` 未动（`git status` 可证），发布走 `deploy/publish.ps1` 的正常流程。
3. **本地预览行为不变**：根服务下 `./` 与 `../` 等价（§3 已复算），`& $py serve.py 8000` 的体验不受影响。
4. **建议（不在本次写权限内）**：把「按 `/drug-brand-crossref/` 子路径服务 + 4 语言点击矩阵」做成发布前检查的一步（`deploy/` 不在本次可改范围）。这次的教训是：**只测根路径服务永远发现不了项目子路径的 `..` 越界**。
5. **未覆盖**：`/combo/<slug>.html`、`/atc/<L1-L3>.html` 等长尾页没有逐一点击（它们与已测的 atc/drug/name/maker/cat 走同一条 `i18n.js` src 推导路径，且 §3 grep 证明全站只有 4 个首页内联 ROOT）；如需要可把矩阵里的 `PAGES` 再扩几类重跑。
