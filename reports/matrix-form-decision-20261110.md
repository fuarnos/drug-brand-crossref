## 1. 先修两个口径：任务给的偏差各自成立多少

### 1.1 偏差 1「默认 3 列按总记录数选」——**成立，但方向和预期相反**

`site/build.py` L7921 的 `country_totals` 数的是「每国名字格总数」，不是「有强度的记录数」；
L7927 还无条件把 `US` 插进默认列。这两条都真的在坑人，**但坑法不是「空格被夸大」**：

| 市场 | 记录数 | 其中有强度 | 覆盖率 |
|---|---:|---:|---:|
| CN | 148,889 | 142,432 | 95.7% |
| US | 145,948 | 125,803 | 86.2% |
| AU | 92,414 | 85,510 | 92.5% |
| GB | 65,619 | 53,434 | 81.4% |
| TW | 28,644 | 7,786 | **27.2%** |
| **HK** | **22,302** | **0** | **0.0%** |
| ES | 19,735 | 18,464 | 93.6% |
| CA | 19,705 | 19,702 | 100.0% |
| SG | 7,057 | 6,358 | 90.1% |
| MX | 2,219 | 542 | **24.4%** |

- **HK 的 22,302 条记录一条强度都没有**（源头就没有规格字段，见 `db/schema.sql` 的市场注释）。
  它们全部落到「未公开」那几行 → **A 按总记录数选中 HK，等于把 3 列里的 1 列专门用来展示「未公开」行，
  而所有真规格行在 HK 列上都是空格**。这就是用户看到的「整行空白」。
- 但**空格比反而更低了**：默认 3 列是按「名字格数」挑的最密几列（外加强制插入的 US），所以
  polymyxin 默认 3 列空比 **81.6%** < 全市场口径 **85.8%**；acetaminophen **71.7%** vs **84.9%**。
  **旧报告那个 73.3%（全市场口径）是诚实数，不是被夸大的数**——被选择的 3 列才是「化了妆」的那一版。
- 结论：偏差 1 的真实伤害是「**列没用**」（1/3 的列只能看未公开行），不是「**空格虚高**」。
  A→B 换列能修掉它，见 §4。

### 1.2 偏差 2「规格没归一就跨市场比」——**成立，但只值 0.35 个百分点**

同一个脚本跑两遍：`V0_raw`（数值与单位全按库里原样分组，等价于「不归一」）vs `V1`（本次归一）：

| | 规格行 | ≥2 国行 | **≥2 国占比** | ≥3 国行 |
|---|---:|---:|---:|---:|
| V0_raw（不归一） | 75,902 | 6,771 | **8.92%** | 3,069 |
| **V1（归一后）** | **75,102** | **6,961** | **9.27%** | **3,133** |
| 差值 | −800 行 | +190 行 | **+0.35 pt** | +64 |

归一化把 `g→mg`、`µg/mcg/ug/microgram→µg`、`L→mL`、`1e+06→1000000`、`X/1 mL→X/mL` 全部对齐后，
**只合并掉 800 行、只多认 190 个跨市场规格行（+0.35 pt）**。原因：跨市场的差异几乎不是「写法差异」，而是**规格本身不同**
（各国报批的规格集合不一样：`atorvastatin` 的 20 mg 九国都有，但 30 mg 只有 ES·GB）。
**所以「归一化能救矩阵」这个假设不成立**——它提升的是可读性，不是跨市场命中率；这与旧报告 §B.4 的判断一致，本次给了独立复核。

## 3. 问题 2：归一化强度怎么算、覆盖多少、跳过多少

### 3.1 规则（只做同量纲缩放 + 写法归一，**不跨量纲**）

| 类 | 处理 | 例子 |
|---|---|---|
| 质量 | 换算到 mg（结果 ≤100,000 mg 才换，超限保持原单位——与 `build.py` `_normalized_strength` 同一护栏） | `0.5 g`→`500 mg`、`25 microgram`→`0.025 mg`、`110000 g`→**保持** `110000 g` |
| 容量 | `L→mL`、`ml→mL`、`µl→µL`、`microlitre→µL` | `1 L`→`1000 mL` |
| 效价 | **只归写法，不换算数值**：`iu/I.U./国际单位→IU`、`units/u/单位→unit`、`万iu→万IU` | `6000 unit` ≠ `6000 IU`（两个键） |
| 百分比 | **原样** | `5 %` |
| 比例式（`mg/g`、`mg/mL`、`microgram/actuation`） | **只归单位写法**，数值不缩放（缩放=折算） | `15 mg/g`、`5 mg/mL` |
| 数字 | 定点、无千分位、去尾 0 | `1e+06`→`1000000`、`1000000.0`→`1000000` |
| 每剂量 | 同上；**分母是 1 时省略**（`X/1 mL`≡`X/mL`，纯写法） | `100 IU/1 mL`→`100 IU/mL` |
| 复方 | 各成分归一后**排序拼接**（与成分顺序无关） | `500 mg + 125 mg` |

### 3.2 覆盖 / 跳过（组件行 645,884 纳入；75,481 行被状态过滤）

| 情形 | 行数 | 占比 | 备注 |
|---|---:|---:|---|
| 质量单位直写 `mg`（不动） | 402,849 | 62.4% | — |
| **无强度**（`strength_value IS NULL`） | **92,501** | **14.3%** | 不参与规格比较 → 落成 11,036 个「未公开」行 |
| 比例式单位（`mg/g`、`mg/mL`…） | 19,408 | 3.0% | 只归写法 |
| 容量 `mL` 直写 | 18,545 | 2.9% | — |
| 效价/摩尔/计数（IU、unit、mEq、million…） | 6,530 | 1.0% | **数值不换算** |
| **质量→mg 换算（真动了数值）** | **6,102** | 0.94% | 全部是 `g/kg/µg/ng` 写法 |
| 百分比 `%` | 5,567 | 0.86% | 原样 |
| 超大质量值保持原单位（>100,000 mg） | 617 | 0.10% | 如 `110000 g` |
| 未知单位（原样保留） | 367 | 0.06% | 如 `mCi`、`mmol` 之外的杂项 |
| 容量换算 `L→mL` | 24 | 0.004% | — |
| 每剂量 / 每剂量单位跳过 | 71,199 + 12,873 + 748 + 605 + 35 + 25 + 4 | — | 其中 **7,863 行**因分母=1 而省掉 `1` |
| 状态过滤（discontinued / withdrawn） | 75,481 | — | 与站点渲染一致 |

**真动过数值的只有 6,126 行（0.95%）**——其余全是写法归一。这就是「归一化救不了行数」的量化原因。

> 表里 `per_volume` 那几行是**另计的维度**（同一条组件行既算强度、也算每剂量），不能与上面的行相加；
> 占比列的分母统一是 645,884。

### 3.3 归一化能力的边界：比例式行几乎永远跨不了市场

| 单位类别 | 规格行 | ≥2 国 | 命中率 |
|---|---:|---:|---:|
| 质量 / 容量（`mg`、`mL`、`µg`…） | 62,037 | 6,649 | **10.72%** |
| 百分比 `%` | 1,417 | 117 | 8.26% |
| 效价（IU / unit / mEq…） | 2,371 | 108 | 4.56% |
| **比例式（`mg/g`、`mg/mL`、`microgram/actuation`…）** | **9,277** | **87** | **0.94%** |

比例式占 12.4% 的行，却只有 0.94% 的跨市场命中——因为 A 国写 `15 mg/g`、B 国写 `1.5 %` 时，
我们的红线**不允许折算**，它们永远是两行。这块盲区的上限已经量过（§2.2 `X_mgpg_pct`）：**+0.16 pt**。

- **B2**（附加）：按「有强度的规格行数」排序取前 3。

| 范围 | 策略 | 渲染行 | 格数 | 空格比（合计 / 中位 / P90） | 隐藏空行后 | 被隐藏的行 |

### 4.3 为什么 B 的收益有天花板（结构性，不是参数没调好）

3 列 + 90.7% 的行只有 1 个市场 ⇒ 一行最多填 1 格 ⇒ **空比下限 = 1 − 1/3 = 66.7%**（隐藏空行后）。
B 已经在往这个下限贴：polymyxin 64.9%、insulin 66.7%、acetaminophen 56.6%。
**想让空比继续掉，只能改「行」的形态**（列表没有格子）或改「列的语义」（矩阵视图按行内国家裁列）——
这正是 §5 的判定和 §7 的双视图。

另外，**换列不改变首屏能放几行**：首屏行数由行高（CSS padding × 每格名字行数）决定，
按 v0.10.2 dist 实测 109–148 px/行，1440×900 只能放 3–6 行；行高打到 56 px 才是 10 行。
B 改善的是「这 10 行里有几行有数据、看得到几个名字」，不是「能放几行」。

## 5. 问题 4：判定

任务给的判据：≥40% → 矩阵成立；≤25% → 列表优先；中间 → 双视图。

**实测 9.27%（最宽松 10.94%，最严 6.82%）→ ≤25% → 矩阵不适合做默认形态，列表优先。**

支持这个判定的三条独立证据：

1. **行级**：90.7% 的规格行只有 1 个市场 → 3 列里至少 2 格是空的，且这个空是结构性的（§4.3 的 66.7% 下限）。
2. **页级**：8,054 页里 **6,131 页（76.1%）一个跨市场规格行都没有**；只有 789 页（9.8%）的 ≥2 国占比 ≥40%（见 §6.2）。
3. **首屏级**：按站点排序取前 10 行，全站只有 17.8% 是跨市场行——连最「密」的行都如此。

**但不能一刀切成「全站换列表」**，因为矩阵在少数页上是真有价值（§6、§7）：
789 页 ≥40% 的页面上，矩阵是唯一能一眼对齐 4–9 国名字的形态，列表只能竖着读。

### 10.3 归一函数（核心 60 行，完整版见脚本）

```python
from decimal import Decimal as D

MASS_TO_MG = {"g": D(1000), "kg": D(1000000), "mg": D(1), "µg": D("0.001"), "ng": D("0.000001")}
MASS_ALIAS = {"mcg": "µg", "ug": "µg", "μg": "µg", "µg": "µg", "microgram": "µg",
              "micrograms": "µg", "gr": "g", "gm": "g"}      # 中文单位库里一个都没有（无需映射）
VOL_TO_ML = {"mL": D(1), "L": D(1000), "µL": D("0.001")}
VOL_ALIAS = {"ml": "mL", "cc": "mL", "litre": "L", "liter": "L", "microlitre": "µL"}
POT_ALIAS = {"iu": "IU", "i.u.": "IU", "unit": "unit", "units": "unit", "u": "unit",
             "万iu": "万IU"}                       # 只归写法，数值不动
POT_CANON = {"IU", "unit", "万IU", "mEq", "mmol", "million", "billion", "thousand", "mCi"}

def canon_one(u):
    u = u.strip(); low = u.lower()
    if u == "%": return "%"
    return MASS_ALIAS.get(low) or VOL_ALIAS.get(low) or POT_ALIAS.get(low) or u

def fmt(d):                       # 定点、无千分位：1000000.0 → "1000000"（不出 1e+06）
    s = format(d.normalize(), "f")
    return (s.rstrip("0").rstrip(".") if "." in s else s) or "0"

def norm_qty(value, unit):
    """→ (归一串, 标记)。只做同量纲缩放 + 写法归一；IU/unit/%/比例式一律不换算。"""
    if value is None: return "", "no_strength"
    u_raw = (unit or "").strip()
    if not u_raw: return fmt(D(str(value))), "no_unit"
    if "/" in u_raw:              # 自含比例式：mg/g、mg/mL、microgram/actuation
        a, _, b = u_raw.partition("/")
        return f"{fmt(D(str(value)))} {canon_one(a)}/{canon_one(b.strip().split(' ')[-1])}", "compound"
    u = canon_one(u_raw)
    if u in MASS_TO_MG:
        mg = D(str(value)) * MASS_TO_MG[u]
        if mg <= D("100000"):     # 与 build.py 同护栏：超 100000 mg 不换算
            return f"{fmt(mg)} mg", ("mass_scaled" if u != "mg" else "mass_plain")
        return f"{fmt(D(str(value)))} {u}", "mass_kept_large"
    if u in VOL_TO_ML:            # 同 MASS 逻辑：L→mL、µL→mL，≤100000 mL 才换
        ml = D(str(value)) * VOL_TO_ML[u]
        if ml <= D("100000"):
            return f"{fmt(ml)} mL", ("vol_scaled" if u != "mL" else "vol_plain")
        return f"{fmt(D(str(value)))} {u}", "vol_kept_large"
    if u in POT_CANON: return f"{fmt(D(str(value)))} {u}", "potency_as_written"
    if u == "%":       return f"{fmt(D(str(value)))} %", "percent_as_written"
    return f"{fmt(D(str(value)))} {u}", "unknown_unit"
```

### 10.4 分组与计数（可直接抄的骨架）

```python
kept = []                      # (sid, country, form, release, 强度串, 强度串, pid, 原样键)
for (sid, country, fb, df, rel, status, sv, su, pv, pu, pid, ord_, _mah) in rows:
    if not (status == "active" or (status in ("unknown", "", None) and country in ("HK", "AU"))):
        continue                                   # 与 build.py 的行过滤一致
    st, _flag = norm_qty(sv, su)
    if pv is not None:
        pvtxt, _ = norm_qty(pv, pu)
        if D(str(pv)) == 1:            # 写法归一：/1 mL ≡ /mL
            pvtxt = pvtxt.split(" ", 1)[-1]
        st = f"{st}/{pvtxt}"
    kept.append((sid, country, (fb or df or "").strip(), rel, st, st, pid,
                 f"{sv!r} {su!r}|{pv!r} {pu!r}"))  # 最后一列是「完全不归一」的对照键

base = {}                      # (sid, form, release, 强度串) → {country: 记录数}
for sid, country, form, rel, _sc, st, _pid, _raw in kept:
    if not st:
        continue                                   # 「未公开强度」不是规格
    k = (sid, form, rel, st)
    base.setdefault(k, {})
    base[k][country] = base[k].get(country, 0) + 1

# 每个规格 → 出现在几个不同国家（这就是 §2.1 那张表）
dist = Counter()
for by_c in base.values():
    n = len(by_c)
    dist["1" if n == 1 else "2" if n == 2 else "3-4" if n <= 4 else "5+"] += 1
```
