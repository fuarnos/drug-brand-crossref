## 2. Q8：sync_r2.ps1 打印 Class A 写入数

### 2.1 改了什么

```diff
     $syncArgs = @('sync', $Dist, ("r2:{0}" -f $bucket), '--checksum',
-                  '--transfers', $Transfers, '--checkers', $Transfers) + $confArgs
+                  '--transfers', $Transfers, '--checkers', $Transfers,
+                  '--stats', '60s', '--stats-log-level', 'NOTICE') + $confArgs
```

- 为什么不用 `-v`：`-v` 会给每个文件打一行 `INFO : ... Copied (new)`（全量 ≈ 11.7 万行），发布日志会被刷爆；
  `--stats-log-level NOTICE` 只把**统计块**抬到 NOTICE，日志里每 60 s 一块 + 结束时一块，体积可忽略。
- 头部注释（`.NOTES`）补了读法：取**最后一条** `Transferred: N / N, 100%` 的 N（= 写入文件数 ≈ Class A PUT；
  平均 7.8 KB/文件，1 文件 = 1 PUT），耗时看 `Elapsed time:`；没东西可写时 rclone 只打
  `Transferred: 0 B / 0 B`（无 N/N 行）→ 按 0 处理。
- `-CheckOnly` 分支未改；`deploy/verify_live.py` 未改（`git status` 只有两个文件被修改）。

### 2.2 行为等价：改前 / 改后 `-DryRun` 计划文件集

| 夹具 | 改前 | 改后 | 结论 |
|---|---|---|---|
| `site/dist`（真实产物，v0.13.5 同款） | 0 上传 / 1 删除（`fr/`）；Checks 137,324 | 0 上传 / 1 删除（`fr/`）；Checks 137,324 | **逐条一致** |
| `.tmp/q8/dist-touch`（`site/dist` 副本 + 3 个文件追加一字节） | 3 上传（`index.html`、`drug/acetaminophen.html`、`name/tylenol.html`）/ 1 删除（`fr/`） | 同上，路径集合完全相同 | **逐条一致** |

- 两次运行脚本都打印 `OK`、`exit 0`；改前 79.4 s（冷缓存）/ 改后 60.0 s（热缓存）——差异来自文件缓存，
  不是 flag（只改日志）。
- 真实产物 0 上传符合预期：`site/dist` 就是 v0.13.5 已发布产物；唯一计划删除是同步后要重放的
  `fr/` 合成对象（脚本原本就会在同步后 PUT 回去）。

  Select-Object -Last 1

### 2.4 旧发布日志佐证

- `.tmp/sync-v0135.log`：2,122 B / **16 行**，只有 `0 differences found` / `137323 matching files`
  和 `fr/` 回放 / `OK`，**没有 `Transferred:` 行** → 过去只能按 dist 文件数推断「≈13.7 万 PUT」。
- 同一份日志里 check 的 stderr NOTICE 在（`powershell : ... NOTICE: S3 bucket ... 0 differences found`），
  说明**发布流程本来就捕获了 stderr**；缺 stats 纯粹是 rclone 默认 INFO 级别，不是日志没抓到。
- 注意：新增的 stats 是 NOTICE 级 stderr，和现有 NOTICE 一样会触发「`2>&1 | Tee-Object` 让外层退出码变 1」
  这个已知怪癖——判定口径不变，仍看脚本自身 `OK` 行与 `rclone check` 的 `0 differences`。
- 下一次发布（v0.13.6）用改后脚本，日志里每 60 s 会多一块 stats，发布报告直接从最后一块抄
  `Transferred: N / N` 与 `Elapsed time:` 即可（Q8 收尾）。
