## 1. 方法与替代说明（必读）

**替代方法**：DSH 的 **MCP 浏览器**（Playwright + Chromium），没有用 `deploy/first_screen_check.py` 的 CDP 流程，也没起 `--remote-debugging-port`。

- 视口：`page.setViewportSize({width:390,height:844})` / `{1440,900}`，与官方 `--viewports 390x844,1440x900` 同尺寸。
- 条目数：我把 `first_screen_check.py` 第 390–418 行的判定逻辑**原样抄成页面内 JS**（交集面积比 ≥0.90 记 1、≥0.25 记 0.5、元素宽高 <4px 跳过、`drug` 用 first-match 先 `.mkrow` 后 `table.matrix tbody tr`），选择器与脚本 §PAGES 一致：
  - home `.catgrid a` + `.updlist li`；results `#reswrap tbody tr.br` + `tr.grp`；drug `.mkrow`（first-match 回退矩阵行）；atc `ul.atcmembers li` + `ul.atclist li`。
- 横向溢出：`document.documentElement.scrollWidth > window.innerWidth + 1`（与脚本第 543–544 行同口径）。
- 检索：不直接改 URL 重载，而是在首页 `#q` 上派发 `input` 事件（与站点自身 `box.addEventListener('input', …)` 同一条路径），等 1.6–1.8 s 后读 `#reswrap` 行数与 `#meta` 命中数；语言用 `?lang=zh|en|es|zh-hant|fr` 载入。

**局限（写进发布判断前请读）**：

1. **不是官方脚本**：AFCR / band_ratio / chrome 占比 / 悬浮遮挡 / 字号 / 主操作上沿比 / `<details>` 展开 / `?view=table` / 17 项交互冒烟**全部没跑**。本报告只能覆盖「可用性 + 检索 + 徽标 + 首屏条目/溢出 + chip 筛选」。
2. **滚动条口径差**：Playwright 视口有 **15px 经典滚动条**（390 视口 → `clientWidth=375`），官方 headless CDP 是 overlay 滚动条（`clientWidth=390`）。为可比，条目数**同时记了两组**（§5 表内 `390/375` 带注）。
3. **results 数字不可复现**（沿用 v0.11.3 报告的既有结论）：依赖 42.8 MB `data/idx/core.json` 加载完；我这次 `泰诺` 稳定 3 行，但 `#meta` 常驻「部分结果 —— 正在加载完整索引…」，命中总数是**下界**。
4. **无真机 / 无 Safari**：所有数字来自本机 Chromium，iOS `100dvh`、软键盘 sticky 仍未验（沿用 11-10 已知项）。

## 5. 首屏替代测量（req 4）

### 5.1 数字（MCP 浏览器，非 CDP）

视口两档 `390×844`、`1440×900`；条目按官方「≥90% 记 1 / ≥25% 记 0.5」；溢出 = `scrollWidth > innerWidth+1`。

|---|---|---:|---|---:|---|
| `index.html`（home） | 390×844 | **8.5** / 0.0* | 否 | 0 | **不可比**（见 5.3） |
| `index.html?q=泰诺&lang=zh`（results） | 390×844 | **0.5** / 0.5 | 否 | —（v0.11.3 官方 0.5 < 3.0 既有缺口） | 与官方既有缺口一致 |
| `drug/acetaminophen.html` | 390×844 | **5.5** / 5.5 | 否 | 6.5（官方 v0.11.3 实测 6.0） | **略低 1.0 条（−15%）** |

`*` home@390 的 0.0 只出现过一次：**页面刚 `goto` 完、布局还没稳定时测的**（`.catgrid` 12 个元素全部不在视口内）。等布局稳定（≥2 帧，实测 6 s 内不变）后两档宽度都是 **8.5**（9 个 chip：8 个 ≥90% + 第 9 个 809–853px 越界 → 0.5）。**8.5 是可复现值，0.0 是测量时机伪影**，写在这里防止被当成基线。

细节（可复核）：`drug/acetaminophen.html@390` 首行 `.mkrow` 上沿 **y=385**，行高 75–96px；第 1–5 行 100% 可见，第 6 行（y=784，h=76）露出 79% → 0.5，合计 **5.5**。`atc/R06A.html@390` 首屏 8 个 `li`（28 个 ≥90%…按宽度折算 7.5）。所有 8 组的 `<html>`/`clientWidth` 与 `scrollWidth` 相等 → **横向溢出 0**。

### 5.2 溢出与字号

- 横向溢出：**0/8**（4 页 × 2 视口）。
- 未测：AFCR / band_ratio / chrome 占比 / 悬浮遮挡 / 字号（正文 16px、辅助 13px 的结论沿用官方脚本，本轮不重复）。

### 5.3 为什么 `home` 两组「不可比」

- 交接基线：`home@390 = 0`、`home@1440 = 6`（v0.11.3 报告的归因是「市场面板常显 167px 把类别格挤出首屏」）。
- 我的替代测量：两档都是**类别 chip 全部/大部进首屏**（390：chip 上沿 569、`.catgrid` 高 292；1440：chip 上沿 483），6 s 内稳定不变。
- 差异量级（+8.5 / +6.0）远超测量噪声，且 `atc`/`drug` 两组同法测量与官方吻合（±0.5），所以**不是我的方法整体偏松**，而是 home 这一页的状态/视口口径不同（候选：CDP 设备模拟下的字体度量、滚动条、或基线测量的页面状态）。
- 结论：**home 两组不作为发布判据**；官方 CDP 脚本能跑时必须补跑 `--pages home` 对比。入口页条目门槛为 0（`entry` 型，`items_min=0`），即使按官方口径为 0 也不阻塞发布。

### 5.4 `drug@390` 少 1 条怎么看

- 我测 5.5（5 整 + 1 半），交接基线 6.5，官方 v0.11.3 报告实测 **6.0** —— 基线本身在 6.0–6.5 之间浮动。
- 首屏上方 chrome 占 385px（h1 + 搜索 + 167px 市场面板 + 块头/筛选），第 6 行只差 **16px** 就能从 0.5 变 1。字体度量差 1–2% 或滚动条 15px 都足以翻转这半条。
- 判定：**「持平到 −0.5 条（口径内噪声）」**，不建议当回归处理；若官方 CDP 复核仍是 6.5→5.5，再单开 task（属首屏 chrome 偏高，非 v0.11.5 特有）。
