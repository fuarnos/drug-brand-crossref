## 结论（先说结果）

手机现在有两种访问方式，都不依赖云端服务：

1. **同一 Wi-Fi**：`python mobile/server.py`（或双击 `手机看板.cmd`）→ 手机打开终端打印的
   `http://192.168.10.115:8787/?k=<token>`，可存书签。
2. **4G / 外网**：`python mobile/server.py --tunnel` → 起 `cloudflared` 快速隧道，
   打印 `https://xxx.trycloudflare.com/?k=<token>`。**已用公网地址实连验证通过**。

页面上半屏是进度（产品 / 成分 / 碰撞、各国条数、站点构建、仓库状态、最近 5 份报告），
下半屏是待办队列 + 输入框。手机发出的指令进 `inbox/commands.jsonl`（append-only），
**agent 开工时先读队列、执行、回帖**（`inbox/replies.jsonl`），页面上就能看到 `done` / `blocked`。
这条「开工先看队列」已经写进 `AGENTS.md` §7，任何会话都会照做。

## 为什么不是「缓存 20 秒」那么简单

原设计的 `/api/state` 打算每次刷新跑一遍统计，实测**必须改**：

| 函数 | 冷 | 热 | 原因 |
|---|---|---|---|
| `render_dashboard.db_stats()` | 7.06 s | 7.03 s | 30 多条 `count(*)`，`collision` 视图也在里面 |
| `render_dashboard.dist_stats()` | 4.90 s | 4.90 s | `site/dist` **30,259 个文件**逐个 `stat()` |

（命令：`python .tmp/probe_progress.py`，只读开库，2026-10-26）

所以最终实现是**磁盘快照 + 后台线程 + 先返回旧值**：

- 快照 `.tmp/mobile/progress.json`（`computed_at` / `db_mtime` / `dist_mtime` / `payload`，原子写）；
- 启动算一次，之后每 60 秒看 `data/drugs.db` 与 `site/dist/index.html` 的 mtime，变了才重算；
- `/api/state` 只读内存快照，**实测连续 5 次 2 ms**；没有快照时返回 `warming: true`，
  页面显示「正在统计数据…」并 3 秒后重试；
- 「刷新」按钮走 `?fresh=1` 触发后台重算，约 12 秒后页面自己更新。

## 安全边界

- **token 必填**：`?k=` 或首次访问后种下的 `mb_token` cookie（HttpOnly / SameSite=Lax / 30 天）；
  没 token 一律 401，不泄露内容。token 存在 `.tmp/mobile/token.txt`（gitignore）。
- 同 IP 每分钟最多 20 次提交（429 + `Retry-After`），正文 ≤2000 字（400），请求体上限另有限制（413）。
- 所有响应带 `Cache-Control: no-store`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`；
  页面零外链资源。
- 服务对 `data/drugs.db` **只读**（`mode=ro`，复用 `render_dashboard` 的查询）；不碰入库 / 建站 / 发布。
- 手机指令只是文本，页面**不执行命令**；涉及删数据、发布、花钱、改公开口径的，agent 仍按
  `AGENTS.md` §6/§11 先问人。

## 与设计不一致的地方（都是实现方的自主决定）

- 进度改为磁盘快照 + 后台线程（见上），`§4.3` 的字段结构没变，`/api/state` 顶层多了
  `computed_at` / `stale` / `warming` / `refreshing`。
- `site.built_at` 用 `site/dist/index.html` 的完整 mtime（`dist_stats()` 只给 `HH:MM`），
  其余 files / index / drug / name 仍复用 `dist_stats()`。
- 队列展示顺序：未完成置顶、同组时间倒序、最多 50 条；`pending` 子命令只列待办（最早在前）。
- 队列锁加了「>30 秒视为死进程残留，自动回收」——否则被 kill 一次会永久卡死。
- 状态推导严格按「最后一条回帖」；孤儿回帖（指向不存在的指令）在 `load_state()` 里静默忽略。
- 暗色跟随系统、无手动开关；401 页不放 token 输入框（少一个被爆破面）。

## 缺口 / 没验到的

- **没有真实浏览器渲染与截图**：本沙箱里 Chrome / Edge headless 都起不来
  （`mojo/public/cpp/platform/platform_channel.cc:112 Check failed: 拒绝访问`，命名管道被拒），
  `render_dashboard.py` 的截图同样跑不了。页面布局靠静态检查（无 >320 px 固定宽度、13 处
  `overflow-wrap:anywhere`、5 处 `word-break`、grid/flex 无 table、零外链）代替**肉眼确认**。
  → 第一次真机打开时请顺手看一眼 360 px 下有没有横向滚动。
- **构建进度看不到**：`site/build.py` 不写日志文件，页面只能给 `site/dist` 的时间、文件数，
  以及 90 秒内改过时标「可能正在构建」。
- **快速隧道域名每次重启都变**；固定地址要 Cloudflare 命名隧道或 Tailscale（都要装东西/登录，没做）。
- **git 状态与报告列表的新鲜度**跟着快照走（只在 db/dist mtime 变化或点刷新时更新）。
- 三语套件 `tests/trilingual/run_tests.py` 在**管道重定向**下会因 GBK 编码 `✓` 报
  `UnicodeEncodeError`（既有问题，非本次引入）；终端里跑或用 `PYTHONIOENCODING=utf-8` 正常。
  本次用后者跑完整套：67/72、566.5 秒，与既有基线一致。5 个失败案例是查得到的既有缺口
  （见 `reports/trilingual-query-tests.md` §3），不在本次范围。
- 没有推送通知：指令执行完不会响铃，得自己刷新。
- 多用户无权限分级：拿到同一个 token 的人看到、能发的都一样。
