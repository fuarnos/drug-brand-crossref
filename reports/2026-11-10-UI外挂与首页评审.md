## 2. Design Specificity Verdict（先看这条）

**判断：中等偏低——骨架 100% 通用，产品个性只活在 3 句文案里。**

- **人工判断（A）**：换掉 logo 和文案，这页就是任何「可检索目录 + 分类浏览 + 版本更新」站点的首页。真正属于这个产品的只有 4 样：候选集那句红线、『包装上一行字』这个输入承诺、11 个市场的覆盖数字、以及**只在结果态才出现**的身份卡与「不可互换」条。前两样在首屏但很弱，后两样不在首屏。
- **检测器（B）**：`detect` 在 `index.html` 上返回 `[]`（源码与 URL 两条管道均为 0 findings，1280/390 两个视口都是 0）。**这不算夸奖**：检测器只抓机械特征，抓不到「通用骨架」这类判断；反过来，它的阈值（`.tag`/`.st-badge` 13px 时 `tiny-text<12px` 永不触发）也保证它不会替你守住站内 16/13 字号门禁。
- **两者一致的地方**：首页没有发现「AI 味/过度装饰」类硬伤；问题都在 IA 与文案层。

## 3. 优先问题（P0–P3）

### P1-1 ｜ 三语 H1 承诺不一致，且英文 aria-label 混进非英语页

- **位置**：`site/build.py:192`（en）`409`（es）`628`（zh）；`dist/index.html:54, 64, 126` 的 `aria-label="More"/"Suggestions"/"Primary"/"Sections"` 为硬编码英文。
- **冲突**：`docs/ui-overhaul-spec.md` §3.5 首页线框写的是「H1 查一个药名，看它在各国是什么」——zh 守住了，en/es 漂成「识别这是什么药」（像 pill identifier）。
- **影响**：英文/西语用户第一句话就被承诺了错误的产出（识别 vs 跨国对照）；西语/中文用户读屏到一半突然切英文（WCAG 3.1.2 语言标识、4.1.2 名称角色）。
- **改法**：三语 H1 统一到同一语义；aria-label 走 i18n；副标题里「永远是候选集」提成独立一行（16px 正常前景色，不要 14px muted）。

### P1-2 ｜「国家/地区」下拉被前置成首屏主表单行

- **位置**：`dist/index.html:67-81`（`label.sel-label` + `#country`，**12 选项**），文案 `site/build.py:9443`。
- **冲突**：同一份规范写的是「国家/地区筛选（可选，折叠成 More filters）」，当前是完整暴露的表单行——**以规范为准，这是偏离项**。
- **影响**：① 与搜索框同权，像必填；② 用户常常不知道手里这盒是哪个国家（代购/旅行带回），选了等于主动缩小候选；③ 选中后可能得到「Not covered in this country」，而安抚文案在页尾另一屏。
- **改法**：收进已有的 `<details class="mf-details">更多筛选`（组件现成，`site/build.py:3731`），标签改疑问式并标「可选」，URL 仍保留 `?country=`。

### P2-3 ｜ 检测器唯一的真阳性：ATC 页徽章 padding 归零（153 处聚合）

- **位置**：`site/build.py:3169` `.atcmembers .st-badge{padding:0 5px;line-height:1.2;font-size:13px}`，覆盖了 `3427` 的 `padding:2px 6px`。
- **证据（B）**：`/atc/A.html` 40 条、`/atc/L.html` 73 条 `cramped-padding`（A 页实际 2226 个 `st-badge`，报告只抽样 40 条，不要读成「40 处」）。
- **根因**：`build.py:3171-3174` 的注释自述这是「390px 下 4 徽章行压到 48px」的取舍，但注释还停在 12px——**字号 12→13 后 padding 没复核**，徽章变高、内边距仍 0。
- **同类真阳性**：`/drug/pregabalin.html` 的 `skipped-heading`——DOM 实测 `<h1>×1、<h2>×0、<h3>×11`，每个市场区块直接上 h3（WCAG 1.3.1，读屏无法按层级跳读）。
- **改法**：徽章 padding 至少 `1px 5px` 并复核 390px 行高；市场区块标题降为 h2、其内条目 h3。

### P2-4 ｜ 1280 宽度下页头挤压、两个 Categories、面板互相压住

- **位置**：`dist/index.html:26-56`；CSS `site/build.py:3682 / 3790-3794`；双语开关挂载点 `assets/bilingual.js` 的 `injectToggle()`。
- **证据**：1280 内容带只有 853px（`--band-w:66.67vw`），而头部最小内容宽 ≈900–1030px → zh/es 出现词中断行（`docs/img/ui-surface-home-1280.png` 里「按类/别」「中/文」各占两行）；`nav.querySelector('.langs')` 恒为 null，双语开关退回 `nav.appendChild`，**正好变成第 6 个导航项**。
- **影响**：1280 是笔记本最常见宽度；open 截图里 Categories 面板直接盖住 h1 与输入框。
- **改法**：桌面隐藏 `.sn-right .qcat`（主导航已有 Categories）；`.sn-right summary{white-space:nowrap}`；补 `.langs` 占位；`header details` 互斥 + 点外部关闭；**把 1280x800 加进 `first_screen_check.py` 的 VIEWPORTS**——现有 390/768/1440/2560 恰好漏掉带宽切换与头部 nowrap 的交界档。

### P2-5 ｜ 首屏唯一的加载反馈在页尾，且是工程语言

- **位置**：`#loadhint`（`dist/index.html:112`），文案 `site/build.py:9487` 与 i18n `216-219 / 434-438 / 647-650`。
- **影响**：首次搜索是最焦虑的一段（要下分片），解释它的话却在第二屏之外，内容是「中位约 1.0 MB，gzip 约 0.16 MB」，用户无法据此做任何行动；真正需要它的时刻（打了字没反应）`#meta` 还是空的。
- **改法**：字节数搬去 about / what's-new；搜索框下方一句人话「首次搜索需要 1–3 秒，之后更快」并用 `aria-describedby` 关联 `#q`；聚焦输入框即触发索引加载。

### P3-6 ｜ 搜索是唯一主操作，却没有可见提交控件

- **位置**：`dist/index.html:60-65`（`#q` + `#ac`，无 button），`/` 逻辑 `site/build.py:6084`。
- **改法**：加 44×44 图标提交按钮（`aria-label` 走 i18n）、输入框右侧 13px 灰字提示「按 / 聚焦」、移动端 `enterkeyhint="search"`。

## 5. 待核实（不要据此下结论）

**`results@390` 报「首屏条目 0.0 + first-result 未完整可见」，与截图矛盾。** `.tmp/fs_shots/fs-results-390x844.png` 里第一张身份卡（`泰诺 →` 四个成分、规格、覆盖市场、23 条记录、三个动作按钮）已完整渲染在首屏内。

两个可能：① 量尺在 `Page.loadEventFired` 后只等约 0.85 s 就量，抢在懒加载索引解析完之前（该页首屏文案「正在加载完整索引…」）；② `items` 选择器 `#reswrap tbody tr.br` 与 v0.10.3 之后的结果卡片结构不再匹配。

自动复核没做成：Chrome 与 Edge 在本机都无法拉起 `--remote-debugging-port`（`ui_surface_check.launch_chrome` 连续失败，端口 9333/9461 均不通），已放弃该路线。**建议**：把它写进跟进提醒，下次改站点时用 `--shots` 前后帧对比一次性判定；如果是时序问题，量尺要加「等待结果行出现」的显式等待，否则 results 页的数字会一直假红。

## 6. 做得好的（别在改版里弄丢）

1. **搜索框是「键盘 + 读屏都能用」的**：48px 高、16px 字、`sr-only` 真标签、`#ac` 有 `role=listbox` 与 `aria-selected`、`#meta` 是 `aria-live=polite`。同类站点多数只做到「能打字」。
2. **把「首搜慢」做成了可见过程**：分片快车道 → 部分结果 → 骨架屏 → 完成，`prefers-reduced-motion` 有降级。这是把性能约束翻译成体验的少数正确做法。
3. **示例按钮按语言本地化并带俗称样例**（泰诺 / 两只青蛙 / Lipitor 20mg），一键跑通真实路径；关掉引导后不闪。这套「示例即教学」比截图教程有效得多。
4. **检测器在首页 0 命中**（两个视口、两条管道），说明现有 CSS 没有明显机械硬伤。

## 7. 次要观察

- **同一页 11 个市场三种顺序**：`#country`（US GB CN…）、Markets 面板（US CN GB…）、覆盖条（AU CA CN…）。建议单一常量，覆盖条链到 `coverage.html#market-XX`。
- **中立信息用了警示色**：`.notice` 直接吃 `--warnbg`（`build.py:3231`），覆盖统计块长得像报错条；而真正的警示 `.idwarn` 是同一个底色，两种语义共用一个色。
- **`u1.step3_hint` 指向首页不存在的组件**：让用户看结果顶部的「国家/地区叫法」横排，而 `.u2bar` 只在结果态存在。
- **`#q` 缺 `role="combobox"`**：有 `aria-autocomplete` / `aria-controls` / 运行时 `aria-expanded`，部分读屏不会播报候选数量。
- **带 `?q=` 时 H1 仍是营销语**：`setH1('', 'home.h1')` 只在清空查询时调用（`build.py:5255`），`ui-overhaul-spec.md` 的 P0-1 点过这条，身份卡补上了、H1 没跟上。
- **视觉母题**：暖白底 + 衬线大标题 + 单一深绿 accent，正好落在外部「AI 生成页面常见特征」清单的第 1 类（米底 + 衬线 + 单一饱和强调色）。**项目规范优先**，不建议为此改视觉方向；仅提示：如果将来要「更像这个产品」，差异化应该来自「一药多国名字」这种结构性母题，而不是换配色。
